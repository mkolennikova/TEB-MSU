# Сравнение `src_ctrl` и `src_dev` на CAPITOUL

Стенд собирает `src_dev` с `-DTEB_UPSTREAM_CONS_BUGS` и обычный `src_ctrl`
(без `TEB_UPSTREAM_CONS`). Каждая конфигурация создаётся изменением общего
словаря `tests/CAPITOUL/namelist/namelist.nml`; **один и тот же полученный файл**
передаётся обоим деревьям. Во всех случаях CBS выключена по умолчанию `src_dev`:
ключ `teb_lcbs_scheme` отсутствует в общем словаре и не принимается `src_ctrl`.

```powershell
python python_tests/ctrl_dev_base_test/compare.py --toolchain-dir C:\msys64\ucrt64\bin
```

По умолчанию выполняются короткий прогон (100 строк) и полный CAPITOUL (17999
строк) для каждого случая. `--smoke-only` запускает только короткие прогоны;
`--skip-build` использует сборки в `build/ctrl_dev_base_test/bin/`. `--out-dir`
меняет каталог результатов. В `report.md` и `report.json` сохраняются результаты
по каждому случаю, хеши словарей и программ, число строк с дождём и снегом,
число строк со снежной долей дороги и кровли, первые расхождения и максимальные
ошибки. Логи и CSV сохраняются в каталоге стенда.

Для московского форсинга за январь 2024 года из `TEB_Work`:

```powershell
python python_tests/ctrl_dev_base_test/compare.py `
  --forcing-nml W:\TEB_work\Moscow_winter\forcing_ERA5\namelist_forcing.nml `
  --replacement-wind W:\TEB_work\Moscow_winter_nosnow\forcing_ERA5\forcing_txt\Forc_WIND.txt `
  --irrigation-months 1 1 `
  --out-dir build\ctrl_dev_moscow_winter `
  --toolchain-dir C:\msys64\ucrt64\bin
```

Полный прогон здесь составляет 744 шага (743 строки результата). Исходный
`Moscow_winter/Forc_WIND.txt` повреждён: содержит только 240 строк и неверные
значения с первой строки. Файл ветра из `Moscow_winter_nosnow` содержит все
744 строки; остальные файлы этих двух наборов совпадают побайтно, кроме снега.
Стенд копирует `Moscow_winter/forcing_txt/` в каталог результатов, заменяет
там только ветер и прописывает путь к копии в создаваемый словарь. Данные
`TEB_Work` не изменяются; источники и хеши записаны в отчёте. `--forcing-dir`
задаёт другой исходный каталог данных, если он нужен. Январское расписание
полива в команде выше искусственно включает этот режим для проверки ветки;
остальные параметры берутся из общей базовой конфигурации CAPITOUL.
В январском форсинге `shade` не срабатывает: температура внутри здания остаётся
ниже порога применения штор. Сравнение `src_ctrl` и `src_dev` в этом случае
выполняется, но общая проверка активности возвращает `fail` и код выхода 1.
Отчёт отдельно показывает результат сравнения и результат проверки активности.

Для расширенного периода с 1 декабря 2023 года по 1 мая 2024 года используется
проверенный набор `D:\TEB_work\Moscow_D5_2023-24` (3649 часовых отсчётов):

```powershell
python python_tests/ctrl_dev_base_test/compare.py `
  --forcing-nml D:\TEB_work\Moscow_D5_2023-24\forcing_ERA5\namelist_forcing.nml `
  --irrigation-months 1 4 `
  --out-dir build\ctrl_dev_moscow_2023_24 `
  --toolchain-dir C:\msys64\ucrt64\bin
```

В этом прогоне все 16 сравнений двух деревьев прошли (8 конфигураций × короткий
и полный прогоны; 3648 строк полного вывода). Полив искусственно включён с
января по апрель, чтобы проверить соответствующую ветку. `shade` и за этот
период не влияет на результат: максимум `TI_BLD` в базовом случае около 295.57 K,
ниже порога применения штор 297.16 K. Поэтому общий статус стенда — `fail` по
активности при `pass` по сравнению результатов.

## Случаи

| случай | изменения базовой конфигурации |
| --- | --- |
| `base` | сад и зелёная кровля выключены; `teb_lshade=.FALSE.` |
| `garden` | сад включён, `fr_garden=0.11`, `PROXY_OLD` |
| `greenroof` | зелёная кровля включена, `teb_frac_gr=0.3`, `PROXY_OLD` |
| `garden_greenroof` | сад и зелёная кровля включены одновременно |
| `irrigation` | дорожный полив включён при летнем расписании базового словаря |
| `wang_zd` | `teb_itype_wind=1`, `urb_zd_town='0.4H'` |
| `no_bem` | `teb_itype_bem='DEF'`, `teb_frac_gz=0.0` |
| `shade` | `teb_lshade=.TRUE.` при включённом BEM |

Для `garden`, `greenroof` и их комбинации используется историческая схема
`PROXY_OLD`, общая для двух деревьев. Во всех остальных случаях сад и зелёная
кровля выключены. Доля остекления при выключенном BEM должна быть нулевой:
иначе оба драйвера останавливаются.

## Критерий

Время и 12 общих колонок форсинга должны совпадать точно. Численные поля
сравниваются по заранее заданному перечню с допуском
`abs(dev-ctrl) <= 1e-10 + 1e-10 * max(abs(dev), abs(ctrl))`.
Неконечные значения, отсутствие обязательной колонки, неправильное число строк
или несовпадение форсинга дают ошибку. Различия текста чисел в пределах допуска
показываются в отчёте и сами по себе не нарушают критерий.

`SOLAR_PROD` записывается в `src_ctrl`, но отсутствует в `src_dev` при выключенных
панелях. `WIND_TOP` имеет разный смысл при `teb_itype_wind=0`, поэтому исключён
для этих случаев; в случае `wang_zd` он сравнивается. В случае `no_bem`
`HVAC_COOL` и `HVAC_HEAT` отсутствуют в `src_dev`, а `H_WASTE` в `src_ctrl`
остаётся неинициализированным из-за D6. Эти исключения прописаны только для
соответствующего случая; прочие общие физические поля сравниваются обычно.
`LE_WASTE` также затронут D6, но не является общей колонкой.

Полный прогон проверяет фактическую активность добавленных режимов: ненулевые
потоки сада и зелёной кровли, а для полива, Wang, отключения BEM и штор — отклик
относительно базового `src_dev`. Неактивный случай считается неуспешным.

Тест сравнивает общие выходы, но не все внутренние состояния. В частности,
`PIMB_ROAD` из D10 не выводится в общую таблицу и требует отдельной проверки.
