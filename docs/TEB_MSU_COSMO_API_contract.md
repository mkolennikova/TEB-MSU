## 1. Граница и правила чтения таблиц

Матрица содержит все **158 обязательных** аргументов (116 IN, 33 INOUT,
9 OUT), все **44 OPTIONAL OUT** и **7 OPTIONAL IN** (`teb_snow_check`,
`teb_ctype_exch_road/roof/canyon`, `urb_d_rf/rd/wl`). Всего 209 аргументов. Нумерация соответствует подписи
`A:src_api/sfc_teb.F90`; автоматическая сверка исключает пропуски/дубликаты.
Источники H прочитаны в `H:src/sfc_interface.f90`, существующий вызов — строка 2807.
Обозначения A/H/B — в §1 плана.

`R` = REAL(`teb_real_kind`), `I` = default INTEGER, `L` = default LOGICAL,
`C(k)` = CHARACTER(LEN=k). Для GNU 15/Linux `R` — 64 бита,
`I/L` — 32 бита, `vpp=wp=teb_real_kind=8`. Модуль `kind_parameters`
H после `3499a0f` не менялся. Старый протокол 8.1 подтверждает числовой
профиль, но текущую A с новой подписью нужно пересобрать и проверить заново.
`N=nproma`, активное окно `1:n_landgp(ib)`, городская маска `sa_uc>0`.
Индексы рабочих массивов `_t` соответствуют упакованным land-point индексам;
`ifull=mind_landgp(il,ib)` задаёт элемент полей `_b`.

| Код | Cold-start и restart-владелец |
| --- | --- |
| C | Часы, дата и окно задаются H; на restart сохраняется исходная ось `ydate_ini/ntstep`. Нулевой `ntstep` означает cold-start, его нельзя повторять при загрузке restart |
| F | Атмосфера H обновляет вход каждого подшага; TEB не хранит его между колонками |
| P | Конфигурация/постоянные поля принадлежат H; при restart должны соответствовать сохранённому состоянию |
| E | Состояние и потоки внешней поверхности вычисляет и сохраняет H; логика лагированного обмена — §2 |
| S | Прогностическое/межшаговое поле H; после каждого вызова выгрузить в свою ячейку, провести pack/unpack и restart. На тёплом вызове не подставлять cold-значения |
| D | Текущая диагностика, определённая только в обработанных городских точках. Историю и нужные restart-значения хранит H |

Векторные константы в столбце источника означают отдельный заполненный массив
`R(N)`, а не скалярный actual-аргумент. Строковые значения сначала присваиваются
константам/переменным CHARACTER требуемой длины C(k) с дополнением пробелами;
короткий литерал нельзя напрямую передавать в dummy большей фиксированной длины.
API принимает положительное число слоёв крыши, дороги и стен; для пола
требуется пять слоёв. Необязательные `urb_d_rf/rd/wl` задают общие для блока
профили толщин длиной `NROOF_LAYER/NROAD_LAYER/NWALL_LAYER` соответственно.
Для числа слоёв, отличного от пяти, соответствующий профиль обязателен.
Без профиля при пяти слоях используются библиотечные толщины. Текущая
конфигурация хоста H сохраняет пять слоёв всех поверхностей. `teb_hour_seconds` имеет форму **(1)**,
общую для блока; `teb_fai` — **(N,8)**. Фильтры логирования — I(0), без CSV.
Все входные буферы заполняются детерминированно и вне активной маски;
выходы вне маски читать нельзя. INOUT вне маски должны сохраняться.

## 2. Обязательные преобразования и порядок обмена

1. H передаёт `teb_snow_check=.TRUE.` на каждом вызове `teb_interface`.
   Точное значение неопределённой величины импортируется как `teb_undef`
   из `sfc_teb`; прямой доступ H к `MODD_SURF_PAR` не требуется.
   Дата вычисляется через `get_utc_date` с календарём H. Шаг — текущий `zdt`
   поверхностной схемы, номер `ntstep` не сдвигается при переходе к другому блоку.
2. `urb_alb_*_th` передаётся как отражательная доля; A сам вычисляет 1−alb.
   Рабочие H `teb_emis_gd_t/teb_emis_gr_t` также несут тепловое альбедо,
   но одноимённым входам A нужна **эмиссивность**: передать `1−значение H`.
   Выход A `teb_emis_town` преобразовать в `teb_alb_th_t=1−ε` после вызова.
3. H уже заполняет внешние H/LE/испарение с противоположным знаком COSMO:
   использовать эти `_t` без второго изменения знака. Потоки стока внешних
   поверхностей входят как kg/m² за `zdt`; `TEB_FILL_EXT` делит их на `zdt`.
   Выходы A `teb_runoff_town` и `teb_snow_melt` — интенсивности: H умножает
   их на `zdt` один раз перед присваиванием прежним буферам количества за шаг.
4. Сад на cold-start берёт T/q/потоки природного тайла 1; на тёплом шаге —
   сохранённый результат `TERRA_GARDEN`, тайл 3. Сохранить этот лаг: сначала
   A, затем TERRA_GARDEN с новыми каньонными T/q/u/v, радиацией и tch/tcm.
   Природные альбедо и `gz0_b(ifull,1)/g` остаются текущим источником свойств.
5. Для кровли источником остаётся природный тайл 1, как в существующем H.
   Недостающие `teb_z0_gr` и `teb_qs_gr` берутся **из того же тайла**: `gz0/g`
   и `qv_s`. Это приближение внешней кровли H, не независимая модель её почвы.
   В первом coupled-кейсе кровля выключена; принятие этого режима — шаг 11.
   `qv=0.3 kg/kg` не допускается; вариант воспроизведения старой PHU=0.3
   требует `0.3*QSAT(Ts,ps)` и отдельной явно выбранной конфигурации.
6. Потоки города уже включают сад. В H тайл 2 имеет вес доли города,
   а тайл 3 — **нулевой вес** в осреднении; он обслуживает внешнюю модель сада.
   Не добавлять сад второй раз и не умножать выходы API на `sa_uc` до штатного
   осреднения H. Снежные величины с нормировкой на непроницаемую часть сохраняют
   этот смысл в прежних TEB-буферах H, как B; площадной бюджет проверяется шагом 10.
7. Семь историй хоста: `teb_troad_now` получает OPTIONAL `teb_troad_before`;
   шесть агрегатов `teb_tstown_s/wstown/tssnow_town/wsnow_town/rsnow_town/hsnow_town`
   копируются в соответствующие `*_now` **до** обновления A. На cold-start
   историю этих шести агрегатов задать первыми возвращёнными значениями;
   при отсутствии снега не читать XUNDEF как физическую температуру/плотность.
   Это история H; внутренние `DMT%*_NOW` последней колонки экспортировать нельзя.

Первый вариант: схема BEM/DEF, кондиционирование, ветер и сад — из `data_runcontrol`;
сад — `EXT`, CBS/панели/полив/шторы выключены, кровля выключена в кейсе.
Дополнительные общие константы ниже повторяют §4.2 плана, включая нулевые
сдвиги уставок, `z0='0.075H'`, `zd='H/3'`, UTC=3 для московского кейса.
Их нельзя заменять offline-defaults. Внешние входы кровли и неактивных опций
всё равно заполняются; выключенная опция не разрешает неопределённую память.

### 4.2 Настройки вне публичной подписи

Не переносить offline-bindings `TEB_BIND_Z0/TEB_BIND_Z0H` в H. Значения z0
дороги/крыши/снега и правила z0h дороги/крыши/города сейчас не имеют отдельных
аргументов в `sfc_teb`. Базовый профиль использует библиотечные defaults;
нестандартные значения требуют отдельно согласованного расширения A (§6.4
плана). Списки отношений сада/зелёной крыши тоже обслуживаются offline;
обязательные аргументы 143/144 этого API остаются скалярными REAL.
Имена CBS в split-неймлисте `teb_cbs_hw_thresh/width` не меняют dummy
146/147 `teb_tau_hw_thresh/width`.

## 6. Приёмка реализации

1. При сборке H получает ровно один `sfc_teb` — из A; старые B-объекты и H-обёртка
   исключены. Архив стоит после потребителей H; `.mod` соответствует тому же профилю.
2. Каждый actual из таблиц имеет указанный kind/форму; все 158 обязательных и
   44 запрашиваемых OPTIONAL OUT и 7 OPTIONAL IN проверяются
   модульным интерфейсом компилятора.
3. Пакет реального H для неодинаковых колонок сравнивается с отдельными вызовами A:
   cold/warm, несколько блоков, хвост, маска и индивидуальное атмосферное воздействие.
4. Непрерывный расчёт и файловый restart COSMO сохраняют состояние/историю;
   повторяется тот же номер модельного шага и конфигурация, cold-start не выполняется.
5. Короткие coupled-кейсы отдельно проверяют знак/площадь/накопление потоков и
   снежную нормировку. Сравнение A с исправленным B не требует совпадения разных
   физических схем и материалов; различие адаптера устанавливается на одинаковых
   входах A, а не подгонкой A к B.

Контрольный срез — текущая C `515112f`; его бинарник и численные repeat/restart
нужно зафиксировать по обновлённому 8.1. Прежний
`urban_repeat_20261115/artifacts/lmparbin_ground_clean` относится к `3499a0f`
и остаётся архивным протоколом четырёх шагов на 64 MPI. Он не проверяет новые
restart, road-only ZQ0 и garden-PAC_GD изменения. Дорожная структура ZQ0 перенесена в A и src_ctrl.
Остальные физические различия B/A перечислены в §4.2 плана; адаптер принимается сравнением с той же A.
