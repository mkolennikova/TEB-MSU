# tau-схема потоков дороги и сада (TEB-Ru): постановка, математика и реализация

Документ описывает **реализованную** tau-схему TEB-Ru: назначение, физический
смысл, математику бюджетов, свойства, численные особенности и диагностики. Это
описание текущего состояния схемы.

Смежные документы:

* `TEB_Ru_garden_diagnostic_scheme.md` — диагностическая прокси-модель сада
  (включая её τ-ветви «сад↔каньон» / «сад↔атмосфера»);
* `TEB_Ru_source_defects.md` — дефекты исходного TEB, найденные и исправленные
  в ходе работы;
* `TEB_Ru_change_history.md` — история версий схемы, отвергнутые варианты и
  протоколы измерений.

> Состояние кода: коммит `c37b29c` (2026-09-20), ветка `MV_devs`.

**Аннотация.** Классический TEB обменивает дорогу с воздухом каньона, а каньон —
с воздухом уровня форсинга. Для разрежённой застройки (H/W → 0) каньона
фактически нет, и такая двухслойная конструкция приписывает поверхности лишний
термический слой. tau-схема вводит вес τ ∈ [0, 1] доли обмена, идущей «через
каньон»: остаток `(1−τ)` трактуется как обмен поверхности напрямую с воздухом
уровня форсинга. При τ → 0 дорога работает как плоская поверхность, при τ = 1
воспроизводится исходный TEB. Температура воздуха, которую «видят» поверхности
каньона, строится как τ-релаксация двух крайних членов — классического узла
каньона `T_CAN0` и температуры свободного слоя `T_CAN1`, полученной по теории
подобия Монина–Обухова на уровне H/2.

## 1. Назначение, конфигурация и место в коде

**Назначение.** tau-схема описывает переход от плотного каньона к отдельно
стоящему зданию:

* при τ = 1 поверхность обменивается с воздухом каньона (классический TEB);
* при τ = 0 — как плоская поверхность, напрямую с воздухом уровня форсинга;
* при промежуточных τ обмен расщепляется на две ветви с весами τ и 1−τ.

Схема применяется к **дороге** (бюджет дороги, узел температуры и узел влажности
каньона), к **снегу на дороге** (ветвь «снег↔атмосфера») и к **саду** (ветви
«сад↔каньон» / «сад↔атмосфера», см. garden-документ). Стены и окна, крыши,
трафик и мусорное тепло схемой не расщепляются (см. §6).

**Конфигурация (namelist `tebparam`):**

| ключ | смысл | значение по умолчанию |
| --- | --- | --- |
| `teb_ltau_scheme` | включить tau-схему | `.FALSE.` |
| `teb_tau_hw_thresh` | H/W, при котором τ = 0.5 | `0.5` |
| `teb_tau_hw_width` | ширина tanh-перехода | `0.25` |

Флаг хранится в `TOP%LTAU_SCHEME` (`src/src_struct/modd_teb_optionn.F90`), пороги —
в `TOP%XTAU_HW_THRESH` / `TOP%XTAU_HW_WIDTH`.

**Вес τ** вычисляется один раз на шаг в `TEB_GARDEN`
(`src/src_teb/teb_garden.F90`, вложенная функция `TAU_URBAN`):

```fortran
IF (TOP%LTAU_SCHEME) THEN
  ZTAU(:) = TAU_URBAN(T%XCAN_HW_RATIO(:), TOP%XTAU_HW_THRESH, TOP%XTAU_HW_WIDTH, T%XBLD_HEIGHT(:))
ELSE
  ZTAU(:) = 1.
ENDIF
```

При выключенной схеме τ = 1 **точно** (умножение на `1.` и нулевое слагаемое),
поэтому выключенная схема воспроизводит исходную модель бит-в-бит (см. §8).

**Куда передаётся τ.** `ZTAU` идёт как `PTAU` в `TEB` (бюджет дороги и его
диагностики) и в `AVG_URBAN_FLUXES` (бюджеты температуры и влажности каньона), а
также в `GARDEN_TAU` (ветви сада). Полный список мест:

| место | что τ взвешивает |
| --- | --- |
| `src/src_teb/teb.F90` (раздел бюджета дороги) | эффективную проводимость дороги и её эталонный воздух для `ROAD_LAYER_E_BUDGET` |
| `src/src_teb/avg_urban_fluxes.F90` (узел температуры каньона) | вес дороги и снега на дороге в `T_CAN0` |
| `src/src_teb/avg_urban_fluxes.F90` (узел влажности каньона) | вес дороги и снега в `PQ_CAN0` |
| `src/src_teb/teb_garden.F90` → `src/src_proxi_SVAT/garden.F90` (`GARDEN_TAU`) | каньонную и атмосферную проводимости сада и его эталонный воздух |
| активация расщепления сада | `LTAU_SPLIT = TOP%LTAU_SCHEME .AND. TOP%CTYPE_GARDEN == 'PROXY_NEW'` |

Внешние интерфейсы драйвера (`namelist`, `sfc_teb.F90`, `call_driver.F90`) при
этом не меняются: τ вычисляется внутри `TEB_GARDEN_STRUCT` и передаётся дальше
штатными аргументами.

## 2. Обозначения

| символ | смысл | единицы |
| --- | --- | --- |
| `A_rd` | проводимость дорога↔воздух каньона (`PAC_RD`) | м/с |
| `A_atm` | проводимость дорога↔уровень форсинга (`PAC_ROAD_ATM`); включает профиль `ln(z_ref/z0h)` и функции устойчивости | м/с |
| `A_top` | проводимость каньон↔уровень форсинга (`PAC_TOP`) | м/с |
| `A_wl` | площадно-взвешенная проводимость стен и окон↔каньон (`PAC_WL·PWL_O_GRND`) | м/с |
| `A_gd` | то же для сада (`PAC_GD·ZGD`) | м/с |
| `A_eff(τ)` | эффективная проводимость дороги в бюджете дороги | м/с |
| `Ca_C`, `Ca_A` | проводимости сада «каньон↔атмосфера» (см. garden-документ) | м/с |
| `T_rd`, `T_c`, `T_a` | температура поверхности дороги, воздуха каньона, воздуха уровня форсинга | K |
| `T_CAN0`, `T_CAN1`, `T_CAN` | температуры воздуха: классический узел каньона, свободный слой (H/2), τ-релаксация (§4.3) | K |
| `Q` | антропогенный поток в объём каньона (трафик + мусорное тепло) | Вт/м²(земли) |
| `θ*`, `u*` | масштабы температуры и скорости трения | K, м/с |
| `κ = 0.4` | постоянная Кармана (`XKARMAN`) | – |
| `PDF_RD`, `PDN_RD` | доли бесснежной и снежной дороги | – |
| `ZRD`, `ZGD` | доли площади дороги и сада в грунтовой части тайла | – |

Все бюджеты записаны в «температурах»: поток `H` переводится в `H/(ρ·cp)` — именно
так он входит в узел каньона в коде (`PH_TRAFFIC/(1−XBLD)/PRHOA/XCPD`).

## 3. Вес τ и его свойства

```fortran
ELEMENTAL FUNCTION TAU_URBAN(HW_RATIO, HW_THRESH, HW_WIDTH, H_BLD) RESULT(TAU)
   REAL, INTENT(IN) :: HW_RATIO, HW_THRESH, HW_WIDTH, H_BLD   ! H_BLD — reserved for future
   TAU = 0.5 * (1.0 + TANH((HW_RATIO - HW_THRESH) / MAX(HW_WIDTH, TINY(1.0))))
END FUNCTION TAU_URBAN
```

то есть

```
τ(H/W) = 0.5·[1 + tanh((H/W − thresh)/width)]
```

Свойства:

* `τ → 0` при `H/W → 0` (отдельно стоящее здание — плоская поверхность),
  `τ → 1` при `H/W ≫ thresh` (плотный каньон); при `H/W = thresh` ровно `τ = 0.5`;
* `width` задаёт ширину перехода: при `width → 0` получается ступенька
  (`tanh` от знака аргумента); вырожденный ноль ширины защищён `MAX(width, TINY(1.0))`;
* параметры нормированы на морфологию, а не на класс застройки: подстановка
  `thresh = urb_h2w` даёт `τ = 0.5` при любой морфологии (используется в
  экспериментах, где нужен «худший случай» τ-осреднения);
* τ — **глобальный** вес шага: он не зависит от поверхности и одинаков для
  дорожной, снежной и садовой ветвей;
* **антропогенные потоки τ-инвариантны**: `AHF_TRAFFIC`, `H_WASTE`/`LE_WASTE`
  входят в бюджеты каньона и города с полным весом при любом τ (их расщепление
  даёт сам бленд, см. §4.3).

Пороги доступны через namelist без переключения кода: `teb_tau_hw_thresh ≫ H/W`
(например `−1000`) даёт `τ = 1` точно, `teb_tau_hw_thresh ≪ H/W` (например `+100`) —
`τ = 0` точно. Это основной приём проверки пределов схемы (§8).

## 4. Математика

### 4.1 Бюджет дороги: эффективная проводимость и эталонный воздух

`src/src_teb/teb.F90`:

```fortran
ZPAC_RD(:)     = PAC_RD(:)
ZPAC_RD_WAT(:) = PAC_RD_WAT(:)
ZT_REF(:)      = PT_LOWCAN(:)
ZQ_REF(:)      = PQ_LOWCAN(:)
IF (TOP%LTAU_SCHEME) THEN
  ZPAC_RD(:)     = PTAU(:) * PAC_RD(:)     + (1.-PTAU(:)) * PAC_ROAD_ATM(:)
  ZPAC_RD_WAT(:) = PTAU(:) * PAC_RD_WAT(:) + (1.-PTAU(:)) * ZAC_RD_ATM_WAT(:)
  DO JJ = 1, SIZE(PTA)
    IF (ZPAC_RD(JJ) > 0.) THEN
      ZT_REF(JJ) = ( PTAU(JJ) * PAC_RD(JJ) * PT_LOWCAN(JJ)                     &
                     + (1.-PTAU(JJ)) * PAC_ROAD_ATM(JJ) * PTA(JJ) ) / ZPAC_RD(JJ)
    ELSE
      ZT_REF(JJ) = PT_LOWCAN(JJ)
    ENDIF
    IF (ZPAC_RD_WAT(JJ) > 0.) THEN
      ZQ_REF(JJ) = ( PTAU(JJ) * PAC_RD_WAT(JJ) * PQ_LOWCAN(JJ)                 &
                     + (1.-PTAU(JJ)) * ZAC_RD_ATM_WAT(JJ) * PQA(JJ) ) / ZPAC_RD_WAT(JJ)
    ELSE
      ZQ_REF(JJ) = PQ_LOWCAN(JJ)
    ENDIF
  ENDDO
ENDIF
```

Иначе говоря:

```
A_eff(τ)   = τ·A_rd     + (1−τ)·A_atm
A_eff_w(τ) = τ·A_rd_w   + (1−τ)·A_atm_w
T_ref(τ)   = [ τ·A_rd·T_c     + (1−τ)·A_atm·T_a     ] / A_eff(τ)
q_ref(τ)   = [ τ·A_rd_w·q_c   + (1−τ)·A_atm_w·q_a   ] / A_eff_w(τ)
```

Анзац «два независимых, каждый по отдельности согласованных пути, соединённых
параллельно» даёт единственную алгебраически замкнутую конструкцию: τ-смесь
эталонного воздуха — ровно то, что делает сумму потоков равной потоку при
смешанных проводимости и воздухе. Аэродинамическая проводимость входит в разность
температур линейно, поэтому фактический поток дороги тождественно равен
τ-комбинации двух «потенциальных» потоков (§4.2).

Эффективные проводимость и эталонный воздух подаются в `ROAD_LAYER_E_BUDGET`,
который решает температуру поверхности `T_rd` и фактические потоки
`DMT%XH_ROAD` (явный) и `PLEW_RD` (скрытый). Сам решатель бюджета не меняется:
он остаётся чистым решателем баланса энергии.

Численные детали:

* эталонный воздух нужен только там, где соответствующая эффективная
  проводимость не равна нулю: у сухой дороги водяная проводимость нулевая, и
  деление на неё давало бы `SIGFPE`; поэтому обе ветви защищены условием
  `> 0` (при нуле берётся каньонный эталон, что для исчезающего потока
  эквивалентно);
* `PTAU` должен быть assumed-shape (`DIMENSION(:), INTENT(IN)`), иначе передача
  срезов массива в `TEB` несовместима с explicit-shape объявлением.

### 4.2 Фактический поток дороги и ветвевые диагностики

Поскольку поток линеен по проводимости при фиксированной температуре
поверхности, фактический поток дороги тождественно равен τ-комбинации двух
«потенциальных» потоков:

```
H_ROAD  = ρ·cp·[ τ·A_rd·(T_rd − T_c) + (1−τ)·A_atm·(T_rd − T_a) ]
        = τ·H_ROAD_CAN + (1−τ)·H_ROAD_ATM
LE_ROAD = τ·LE_ROAD_CAN + (1−τ)·LE_ROAD_ATM
```

`H_ROAD_CAN/ATM` и `LE_ROAD_CAN/ATM` — диагностики: поток, который был бы, если
бы вся дорога обменивалась с воздухом каньона (τ = 1) или напрямую с воздухом
уровня форсинга (τ = 0) при той же температуре поверхности. Тождество
выполняется с точностью арифметики и доходит до вывода через `H_ROAD`/`LE_ROAD`
в `H_TOWN`/`LE_TOWN` и в бюджеты каньона (§8).

### 4.3 Три температуры каньона: `T_CAN0`, `T_CAN1`, `T_CAN`

Температура воздуха, которую «видят» поверхности каньона, строится как
τ-релаксация двух крайних членов (`src/src_teb/avg_urban_fluxes.F90`):

```fortran
T_CAN0 = <узел воздуха каньона без tau>                        ! классический каньон
T_CAN1 = PTA + (theta*/kappa) * PHI_CAN1                       ! свободный слой, уровень H/2
T_CAN  = PTAU * T_CAN0 + (1 - PTAU) * T_CAN1                   ! то, что видят поверхности
```

* `T_CAN0` — температура воздуха каньона, **как если бы τ-схема не работала**:
  дорога обменивается с воздухом каньона (через `PAC_RD` и со своим потоком), стены
  и окна, сад и объёмные источники (трафик, мусорное тепло) греют тот же объём,
  вентиляция объёма — через верх каньона (`PAC_TOP`);
* `T_CAN1` — температура воздуха слоя `[0, H]`, когда **все** поверхности каньона
  обмениваются с атмосферой напрямую: дорога, снег и сад — своими потоками
  поверхность→атмосфера, стены/окна и объёмные источники — как тепло, выделяемое
  внутри слоя;
* `T_CAN` — τ-релаксация обеих величин: именно она подставляется в бюджеты
  поверхностей на следующем шаге (`ZT_LOWCAN = ZT_CANYON` в
  `src/src_driver/call_driver.F90`) и выводится как `T_CANYON`.

Смысл конструкции: каждый источник входит в **оба** крайних члена, а расщепление
выполняет бленд. Чувствительность `T_CAN` к трафику, мусорному теплу или саду
становится `τ·(каньонная) + (1−τ)·(слойная)`, и отдельного «деления площадей» для
объёмных источников не требуется.

#### `T_CAN0` — узел каньона без τ

```fortran
ZINTER = PAC_RD*PDF_RD*ZRD + PAC_GD*ZGD + PAC_WL*PWL_O_GRND + PAC_TOP
T_CAN0 = ( T_ROAD*PAC_RD*PDF_RD*ZRD
         + T_WALL_A*PAC_WL*(1-XGR)*PWL_O_GRND*0.5
         + T_WALL_B*PAC_WL*(1-XGR)*PWL_O_GRND*0.5
         + T_WIN1  *PAC_WL*    XGR *PWL_O_GRND
         + PTA     *PAC_TOP
         + PH_TRAFFIC/(1-XBLD)/(rho*cp)
         + ZRD*PHSN_RD_CAN*PDN_RD/(rho*cp) ) / ZINTER
T_CAN0 = T_CAN0 + ( PTSRAD_GD*PAC_GD*ZGD ) / ZINTER
IF (CBEM == "BEM") T_CAN0 = T_CAN0 + ( XH_WASTE*XF_WASTE_CAN/(1-XBLD)/(rho*cp) ) / ZINTER
```

Это решение стационарного бюджета объёма:

```
ρ·cp·[ A_rd·(T_rd − T_c) + A_wl·(T_wl_eff − T_c) + A_gd·(T_gd − T_c) + A_top·(T_a − T_c) ] + Q = 0

T_c = [ A_rd·T_rd + A_wl·T_wl_eff + A_gd·T_gd + A_top·T_a + Q/(ρ·cp) ]
      / [ A_rd + A_wl + A_gd + A_top ]
```

где `T_wl_eff = (1−XGR)·(T_WALL_A + T_WALL_B)/2 + XGR·T_WIN1`. Поскольку в двоичной
арифметике `1.0·x = x`, при τ = 1 `T_CAN = T_CAN0` совпадает с прежним кодом
**точно** (узел отличается от классического только отсутствием множителей `PTAU`,
которые в него подставлял исходный вариант схемы).

Площадные множители: `ZRD = XROAD/(XROAD+XGARDEN)`,
`ZGD = XGARDEN/(XROAD+XGARDEN)`, `PWL_O_GRND = XWALL_O_HOR/(XROAD+XGARDEN)`; при
выключенном саде `ZRD = 1`, `ZGD = 0`. Все слагаемые узла — **на площадь грунта**.

#### `T_CAN1` — свободный слой на высоте H/2

Тепловой приток слоя (на площадь каньона, как и в `T_CAN0`):

```fortran
ZH_CAN1 = ZRD*PH_ROAD_ATM                    ! дорога -> атмосфера (атмосферная ветвь)
        + ZGD*PH_GD_ATM                      ! сад -> атмосфера (атмосферная ветвь)
        + rho*cp*PAC_WL*PWL_O_GRND*(T_wallwin_eff - PT_LOWCAN)   ! стены + окна
        + PH_TRAFFIC/(1-XBLD)                ! трафик
        + ZRD*PHSN_RD_ATM*PDN_RD             ! снег на дороге -> атмосфера
        + [ BEM: XH_WASTE*XF_WASTE_CAN/(1-XBLD) ]
```

Правила состава слоя (зафиксированы по согласованию):

* **дорога и снег на дороге** входят атмосферными ветвями (`PH_ROAD_ATM`,
  `PHSN_RD_ATM`), т.е. тем потоком, который был бы при прямом обмене с уровнем
  форсинга;
* **сад** входит атмосферной ветвью своего диагностического баланса
  (`PH_GD_ATM`), если включено τ-расщепление сада; без него — потоком модели
  `PH_GD` (см. garden-документ);
* **стены и окна** входят как тепло, выделяемое внутри слоя: используется уже
  посчитанный модельный поток с тем же `PAC_WL` и лагированным `PT_LOWCAN`, что и в
  бюджете фасада, — без нового узла сети (иначе в свободный путь вошла бы скорость
  каньона, т.е. морфология);
* **трафик и мусорное тепло** — объёмные источники с полным весом;
* **крыши** и `XH_INDUSTRY` **не входят**: крыши не являются поверхностью каньона
  (их поток уже идёт напрямую в атмосферу и учтён в `H_TWN`), промышленное тепло
  по решению не учитывается.

Профиль подобия (`u*`, `θ*`, `L`, уровень `H/2`):

```fortran
ZU_ROAD_ATM = MAX( SQRT(MAX(PCD_ROAD_ATM,0.))*PVMOD , 0.01 )     ! u*, м/с
ZTH_CAN1    = ZH_CAN1 / (PRHOA*XCPD*ZU_ROAD_ATM)                 ! theta*, K
ZL_CAN1     = - ZU_ROAD_ATM**2 * PTA / (XKARMAN*XG*ZTH_CAN1)     ! L, м
ZZ_MID      = MAX( 0.5*MIN(T%XBLD_HEIGHT, PZREF), 1. )           ! уровень H/2
PHI_CAN1    = LN(PZREF/ZZ_MID)
            - PSI_H_BD(MIN(PZREF/ZL_CAN1 , 1.)) + PSI_H_BD(MIN(ZZ_MID/ZL_CAN1, 1.))
PT_CAN1     = PTA + (ZTH_CAN1/XKARMAN) * PHI_CAN1
```

* `PCD_ROAD_ATM` — **безразмерный** коэффициент сопротивления диагностики
  «дорога↔атмосфера» (`SURFACE_CD`: `PCDN = (κ/ln(z/z0))²`, `PCD = PCDN·ZFM`),
  поэтому `u* = √PCD·PVMOD` — собственная `u*` модели для этого пути;
* `PVMOD` — тот же ветер, что используется проводимостями модели;
* `PTA` в `AVG_URBAN_FLUXES` — воздух **на уровне крыши** (`ZTA = PTA·PEXNS/PEXNA`
  в `src/src_teb/teb_garden.F90`), поэтому `T_CAN1`, как и `T_CAN0`, согласован
  именно с ним, а не с температурой форсинга;
* уровень `H/2` выбран потому, что это стандартный уровень переменных каньона в
  TEB (`ZZ_LOWCAN = XBLD_HEIGHT/2` в `src/src_driver/call_driver.F90`); при
  `H > z_ref` уровень защищён `MIN(XBLD_HEIGHT, PZREF)` (фактически `z_ref/2`);
* `PSI_H_BD` — функция устойчивости для тепла семейства Businger–Dyer с
  коэффициентами, использованными в `SURFACE_CD`/`SURFACE_AERO_COND`:
  неустойчиво `2·ln[(1+√(1−15ζ))/2]`, устойчиво `−5ζ`; вложенная функция в
  `avg_urban_fluxes.F90`;
* при сильной устойчивости аргумент ограничен сверху единицей
  (`ZETA_STAB_MAX = 1.`): неограниченная `−5ζ` давала бы нефизичные аномалии, а с
  ограничением профиль остаётся ограниченным сверху (`PHI_CAN1` не превышает
  `ln(z_ref/(H/2)) + 5`);
* при `|θ*| < 1e-10` (или при недостоверных входах) используется нейтральное
  значение `PHI_CAN1 = LN(PZREF/ZZ_MID)`; флаг `ZOK_CAN1` отсеивает «мусорные»
  входы (неположительные `PCD_ROAD_ATM`, `ZZ0H_ROAD_ATM`, `PVMOD`), в частности
  ячейки без дорог.

Влажность слоя строится той же конструкцией (те же слагаемые по скрытому теплу):

```fortran
ZLE_CAN1 = ZRD*PLE_ROAD_ATM + ZGD*PLE_GD_ATM + трафик (+ мусорное тепло при BEM)
ZLE_CAN1_SN = ZRD*PLESN_RD_ATM*PDN_RD*XLVTT/XLSTT      ! снег: сублимация (XLSTT)
PQ_CAN1  = PQA + ( ZLE_CAN1 + ZLE_CAN1_SN ) / ( rho*XLVTT*XKARMAN*ZU_ROAD_ATM ) * PHI_CAN1
PQ_CAN   = PTAU*PQ_CAN0 + (1-PTAU)*PQ_CAN1
```

Снежная часть приводится к эквиваленту по `XLVTT` до единственного деления
формулы слоя: скрытый поток снега считается через `XLSTT` (сублимация), а
жидкие источники — через `XLVTT`; приведение сохраняет и физику каждого
источника, и порядок операций (при `PDN_RD = 0` результат не меняется).

Нейтральный предел `PSI_H_BD ≡ 0` даёт контрольную точку `PHI_CAN1 = ln(z_ref/(H/2))`
(для `z_ref = 10` м и `H = 6` м это `ln(10/3) = 1.204`).

#### Свойства ревизии

* `T_CAN = PTAU·T_CAN0 + (1−PTAU)·T_CAN1`; при τ = 1 это ровно `T_CAN0`
  (умножение на `1.0` точно), при τ = 0 — ровно `T_CAN1`;
* `T_CAN1` **не содержит морфологии города**: в нём нет `PAC_TOP`, `ZZ0_TOP`,
  скорости и длины каньона. Морфология остаётся только в толщине слоя (`H/2`) и в
  слагаемых, которые сами затухают с плотностью застройки (площадь стен
  `∝ XWALL_O_HOR → 0`, `H_WASTE ∝ XBLD`, трафик `/(1−XBLD)` при фиксированном
  `ahf_traffic`);
* при `0 < τ < 1` `T_CAN` — **эффективная** температура, а не решение узлового
  баланса каньона. Это осознанное допущение: воздушный узел не входит ни в один
  поток (`H_TWN`/`LE_TWN` собираются из потоков поверхностей), поэтому
  бухгалтерия энергии не меняется;
* потоки города схема меняет только через потоки поверхностей: никакие новые
  слагаемые в `H_TOWN`/`LE_TOWN` не добавляются, каждый источник входит ровно
  один раз.

### 4.4 Бюджет влажности каньона

```fortran
ZINTER = PAC_RD_WAT*PDF_RD*PDELT_RD*ZRD + PAC_AGG_GD*PHU_AGG_GD*ZGD + PAC_TOP
PQ_CAN0 = ( PQSAT_RD*PAC_RD_WAT*PDF_RD*PDELT_RD*ZRD          ! дорога (вес tau)
          + PQSAT_GD*PAC_AGG_GD*PHU_AGG_GD*ZGD               ! сад: без tau
          + PQA*PAC_TOP
          + PLE_TRAFFIC/(1-XBLD)/(rho*XLVTT)
          + ZRD*PLESN_RD_CAN*PDN_RD/(rho*XLSTT) ) / ZINTER   ! снег (вес tau, сублимация)
IF (CBEM == "BEM") PQ_CAN0 = PQ_CAN0 + ( XLE_WASTE*XF_WASTE_CAN/(1-XBLD)/(rho*XLVTT) ) / ZINTER
PQ_CAN1 = <формула свободного слоя, см. §4.3>
PQ_CAN  = PTAU*PQ_CAN0 + (1-PTAU)*PQ_CAN1        ! при выключенной схеме PQ_CAN = PQ_CAN0
```

Структура та же, что у температуры: τ стоит только на дорожных членах (и на снеге
на дороге), а стены и окна, сад, `PAC_TOP` и антропогенные потоки входят с полным
весом. Влажность, которую «видят» поверхности, — τ-релаксация узлов `PQ_CAN0` и
`PQ_CAN1`.

Фазовые переходы учитываются своими теплотами: жидкая влага (лужа на дороге,
стены, трафик, мусорное тепло) — через `XLVTT`, снег — через `XLSTT`
(`XLSTT/XLVTT = 1.1334`), см. `TEB_Ru_source_defects.md`.

### 4.5 Снег на дороге: ветвь «снег↔атмосфера»

Снег на дороге расщепляется так же, как сама дорога. В
`src/src_teb/snow_cover_1layer.F90` сделан второй вызов
`SURFACE_RI`/`SURFACE_AERO_COND` с воздухом и ветром уровня форсинга (та же
шероховатость снега `XZ0SN`/`XZ0HSN`), после чего проводимости и эталонный воздух
агрегируются по τ:

```
ZAC    = τ·ZAC_CAN + (1−τ)·ZAC_ATM
ZTA_REF, ZQA_REF — та же τ-смесь, что у дороги (§4.1)
```

Агрегат используется и в неявном бюджете снега, и в диагностиках, поэтому
фактический снежный поток равен `τ·(снег→каньон) + (1−τ)·(снег→атмосфера)`.

Правила:

* агрегация ограничена ячейками со снегом и пропускается при `τ = 1` или при
  `LTAU_SPLIT = .FALSE.` (снег крыши, который всегда обменивается с уровнем
  форсинга), поэтому прежнее поведение воспроизводится точно;
* снежные члены каньонного узла `T_CAN0`/`PQ_CAN0` берутся из **каньонной** ветви,
  свободного слоя `T_CAN1`/`PQ_CAN1` — из **атмосферной**; агрегированный поток
  питает бюджет снега, а также агрегацию потоков дороги и города;
* нормировка по площади: снежные потоки считаются «на м² снега», поэтому в узлы
  они входят с весом `PDN_RD` (и с `ZRD` — на площадь грунта), а жидкая часть
  дороги — без дополнительного веса `PDF_RD` (см. §4.6);
* ветвевые диагностики `PHSNOW_CAN/ATM`, `PLESNOW_CAN/ATM` (в TEB —
  `PHSN_RD_CAN/ATM`, `PLESN_RD_CAN/ATM`) формируются, но в CSV пока не выводятся
  (§7); в CSV выводятся `WSNOW_RD` (запас воды в снеге на дороге, кг/м²) и
  `TSNOW_RD` (температура снега, K).

### 4.6 Водный путь дороги (лужа)

Мокрый путь дороги τ-консистентен по построению:

* `URBAN_DRAG` считает каньонную (`PAC_ROAD_WAT`) и атмосферную
  (`PAC_ROAD_ATM_WAT`) водные проводимости с одинаковым ограничением по запасу
  воды; `TEB` агрегирует их по τ (`ZPAC_RD_WAT = τ·PAC_ROAD_WAT + (1−τ)·PAC_ROAD_ATM_WAT`)
  и строит по ним опорную влажность `ZQ_REF`. Поэтому дождевые и ирригационные
  слагаемые бюджета дороги уже используют τ-смешанный воздух, а фактический поток
  равен `LE_ROAD = τ·LE_ROAD_CAN + (1−τ)·LE_ROAD_ATM` с точностью арифметики;
* **единый запас воды для обеих ветвей.** Ограничение по запасу применяется к
  агрегату, а не к каждой ветви отдельно:

```
f = min( 1, ZLE_MAX / (τ·q_c_free + (1−τ)·q_a_free) )      (при q_tot > 0, иначе f = 1)
PAC_ROAD_WAT     = f · PAC_ROAD_CAN
PAC_ROAD_ATM_WAT = f · PAC_ROAD_ATM
```

  где `ZLE_MAX = XWS_ROAD/Δt·XLVTT` — максимальный скрытый поток, который может
  дать запас воды, а `PDELT_ROAD` учитывает долю смоченной поверхности. Свойства:
  лужа не может быть истощена одной ветвью в одиночку; τ-декомпозиция сохраняется
  точно (обе ветви масштабируются одним `f`); при τ = 1/0 фактические потоки
  воспроизводятся по классическому правилу соответствующей ветви.

**Нормировка.** Энергобюджет дороги написан в «тайл-средней» формулировке: множитель
`1−PDN_ROAD` вложен внутрь проводимостей, поэтому его выходы уже являются потоками
**на м² дороги**. Потребители поэтому не применяют `PDF_RD` повторно:

* `DMT%XH_ROAD` и `DMT%XLE_ROAD` — тайл-средние потоки без дополнительного веса,
  снежные члены сохраняют одиночный вес `PDN_RD`;
* `DMT%XGFLUX_ROAD = PDF_RD·XRN_ROAD − XH_ROAD − PLEW_RD + PDN_RD·PGSN_RD`
  (здесь `XRN_ROAD` ещё «на м² без снега», поэтому первый вес корректен);
* `URBAN_HYDRO` дренирует лужу **жидким** тайл-средним потоком `PLEW_RD` (без
  `PDF_RD`): снежная сублимация/депозиция уже учтена в `WSNOW_RD`, а талая вода
  вводится в запас с весом снежной доли `PDN_RD`; излишек, не помещающийся в
  ёмкость, уходит в сток, а не теряется;
* водный бюджет (часы без стока, ёмкость лужи масштабируется снег-фри долей
  `WS_ROAD < 0.999·(1−PDN_RD)`):

```
Δ(WS_ROAD + WSNOW_RD) = дождь + снегопад − PLEW_RD/XLVTT − LE_ROAD_SNOW/XLSTT
```

Диагностики мокрого пути: `PAC_ROAD_WAT`, `PAC_ROAD_ATM_WAT`, `PDN_RD`,
`LE_ROAD_WAT`, `LE_ROAD_SNOW`, `WS_ROAD`, `PDN_RF`, `LE_ROOF_WAT`, `LE_ROOF_SNOW`,
`RUNOFF_ROAD`, `RUNOFF_ROOF`.

### 4.7 Сад

Сад — одна поверхность с одной температурой `Ts`; τ интерполирует её связь с двумя
воздушными массами — ровно так же, как `ZPAC_RD`/`ZT_REF` делают это для дороги:

```
Ca_C   = (κ/ln(PZ_LOWCAN/z0))² · max(PU_LOWCAN, Vmin)      ! каньонная ветвь, уровень H/2
Ca_A   = (κ/ln(PUREF/z0))²    · max(PVMOD,     Vmin)      ! атмосферная ветвь, уровень PUREF
Ca_eff = τ·Ca_C + (1−τ)·Ca_A
T_ref  = (τ·Ca_C·PT_LOWCAN + (1−τ)·Ca_A·PTA) / Ca_eff      (аналогично q_ref)
```

Каньонная ветвь питает узел `T_CAN0`/`PQ_CAN0`, атмосферная — свободный слой
`T_CAN1`/`PQ_CAN1`; фактический поток равен `H_GARDEN = τ·H_GARDEN_CAN + (1−τ)·H_GARDEN_ATM`
(то же для `LE`). Расщепление включается только для `teb_type_garden = 'PROXY_NEW'`
(`LTAU_SPLIT`); для `'PROXY_OLD'`, `'EXT'`/`'EXT_NEU'` и при выключенной схеме обе
ветви принудительно равны фактическому потоку. Полное описание схемы сада —
в `TEB_Ru_garden_diagnostic_scheme.md`.

## 6. Свойства и краевые случаи

**При τ = 1.** `A_eff = A_rd`, `T_ref = T_c` в бюджете дороги, вес дороги в
бюджете каньона — `A_rd`, `T_CAN = T_CAN0` (точно, умножение на `1.`). Формулы
совпадают с исходным TEB, поэтому референсные прогоны воспроизводятся
бит-в-бит (см. §8). То же при выключенной схеме (`teb_ltau_scheme = .FALSE.`):
`ZTAU = 1.` и, например, снежное расщепление и расщепление сада просто
пропускаются по условию.

**При τ = 0.**

* бюджет дороги: `A_eff = A_atm`, `T_ref = T_a` — дорога обменивается как плоская
  поверхность с воздухом уровня форсинга;
* бюджет каньона: вес дороги равен нулю — воздух каньона дорогу не «видит», а
  `T_CAN = T_CAN1` точно;
* тождество §4.2 даёт `H_ROAD = H_ROAD_ATM`, `LE_ROAD = LE_ROAD_ATM`.

**Пределы достижимы через namelist** (без переключения кода): `teb_tau_hw_thresh = −1000`
даёт `τ = 1`, `teb_tau_hw_thresh = +100` — `τ = 0`.

**Область значений.** Любая из релаксаций (`T_CAN`, `PQ_CAN`) — взвешенное среднее
с положительными весами `τ` и `1−τ`, поэтому значения всегда лежат между
соответствующими концами (`T_CAN0` и `T_CAN1`).

**Отсутствие вырождений.** `A_eff > 0` всегда (обе проводимости неотрицательны, а
каньонная ветвь сада гарантирует минимум ветра `Vmin = 0.5` м/с); деления на
проводимость защищены условиями `> 0` (§4.1), а нереалистичные входы профиля
отсеиваются флагом `ZOK_CAN1`.

**Численные предохранители профиля `T_CAN1`:**

| величина | значение | назначение |
| --- | --- | --- |
| `ZETA_STAB_MAX` | 1. | верхняя граница аргумента `ψ`-функции устойчивого режима |
| `ZTH_MIN` | 1e-10 K | ниже — берётся нейтральный профиль |
| `ZZ_MID` | `max(0.5·min(H, z_ref), 1 м)` | уровень свободного слоя |
| `ZU_ROAD_MIN` | 0.01 м/с | нижняя граница `u*` в формулах профиля |

**Что схема НЕ меняет:**

| компонента | статус |
| --- | --- |
| обмен стен и окон с воздухом каньона | не τ-взвешен: стены всегда «видят» воздух каньона |
| сад в узле `T_CAN0` (`PAC_GD`, `PTSRAD_GD`) | не τ-взвешен (расщепляется отдельно, §4.7) |
| верхний обмен каньона (`PAC_TOP`, `PTA`/`PQA`) | не τ-взвешен |
| крыши | не участвуют в балансе каньона (обмениваются с атмосферой) |
| трафик и мусорное тепло | входят в бюджеты каньона и города с полным весом |
| городской поток `H_TOWN`/`LE_TOWN` | использует фактические (τ-комбинированные) потоки поверхностей, новых слагаемых нет |
| поток импульса | τ-схема его не делит: `PUW_GARDEN` и трение дороги остаются каньонными |

## 7. Ограничения и открытые вопросы

1. **Случай `H > z_ref`** (например LCZ2: 20 м > 10 м) отложен по договорённости:
   уровень свободного слоя защищён `MIN(XBLD_HEIGHT, PZREF)`, что при `H > z_ref`
   фактически означает `z_ref/2`.
2. **Крыши и `XH_INDUSTRY` не входят в `T_CAN1`** — осознанные решения (крыши не
   являются поверхностью каньона и уже обмениваются с атмосферой напрямую).
3. **Профиль `T_CAN1`** использует простейшие допущения: температура (не
   виртуальная) в числе Ричардсона и в `L`; ограниченная (`ζ ≤ 1`) функция
   устойчивости устойчивого режима вместо формул Деля/Луи; нет поправки на
   подслой (RSL). Это опциональные уточнения, не влияющие на структуру схемы.
4. **Диагностика `PIMB_ROAD`** в `road_layer_e_budget.F90` вычитает
   `ZDF_ROAD·(PHFREE_ROAD + PLEFREE_ROAD)`, тогда как оба потока уже содержат
   `ZDF_ROAD` — вероятное двойное взвешивание в диагностике (физику бюджета не
   затрагивает; см. C1 в §5.7 файла `TEB_Ru_change_history.md`).
5. **Водный путь крыши:** в `URBAN_HYDRO` передаётся `XLE_ROOF`, включающая снежную
   часть с `XLVTT`; `PMELT_RD` (таяние, «на м² снега») добавляется в лужу без
   множителя `PDN_RD` — кандидаты на отдельные правки.
6. **Ветвевые потоки снега** (`PHSN_RD_CAN/ATM`, `PLESN_RD_CAN/ATM`) в CSV пока не
   выводятся: они доступны только диагностической печатью. Выводятся интегральные
   `WSNOW_RD`/`TSNOW_RD`.
7. **Поток импульса** τ-схема не расщепляет: трение дороги и сада остаётся
   каньонным (у сада — `PUW_GARDEN`).
8. **Внесённые правки не в upstream:** дефекты исходного TEB (двойное взвешивание
   `PDF_RD`, нормировка снежных членов, `XLVTT`/`XLSTT`, водный путь таяния)
   исправлены только в TEB-Ru; в `TEB-model/teb` (ветка `master`, состояние 2022)
   они по-прежнему присутствуют — целесообразно завести issue (см. §5.7 файла
   `TEB_Ru_change_history.md`).

## 8. Инварианты и воспроизведение

Схема проверяется по инвариантам, которые обязаны выполняться на любом прогоне:

| № | инвариант | критерий |
| --- | --- | --- |
| I1 | `T_CAN = τ·T_CAN0 + (1−τ)·T_CAN1` | τ, восстановленная как `(T_CAN − T_CAN1)/(T_CAN0 − T_CAN1)`, постоянна по времени |
| I2 | `H_ROAD = τ·H_ROAD_CAN + (1−τ)·H_ROAD_ATM` (то же для `LE`) | невязка на уровне арифметики (единицы 1e-12 Вт/м²) |
| I3 | `LE_ROAD = τ·LE_ROAD_CAN + (1−τ)·LE_ROAD_ATM` и единый фактор ограничения воды для обеих ветвей | ≤ 3.6e-11 Вт/м² / факторы совпадают ≤ 5.6e-17 |
| I4 | предел τ → 1 через namelist | `T_CAN = T_CAN0` (0.0 K), `H_ROAD = H_ROAD_CAN` (~1e-12 Вт/м²) |
| I5 | предел τ → 0 через namelist | `T_CAN = T_CAN1` (0.0 K), `H_ROAD = H_ROAD_ATM` (~1e-12 Вт/м²) |
| I6 | референс (схема выключена, τ = 1) | бит-в-бит с прогонами без τ-схемы по всем общим колонкам (лето и зима) |
| I7 | энергобаланс города `H_TOWN + LE_TOWN + GFLUX_TOWN − RN_TOWN − AHF_TRAFFIC − H_WASTE` | невязка не меняется при включении схемы |
| I8 | водный бюджет лужи (часы без дождя и стока, шаг 1 ч) | замыкание 0.0000 кг/м²·мес |
| I9 | при `f < 1` (ограничение по запасу воды) | `LE_ROAD` равен пределу `WS_ROAD·XLVTT/Δt` |

Воспроизведение (скрипты в репозитории, `python_tests/`):

* `compare_tau_scheme.py` — сравнение τ-прогонов с референсом, пределы τ через
  `--tau-hw-thresh`, суточные графики;
* `check_puddle_water.py` — инварианты водного пути I3, I8, I9 и нормировка
  `LE_ROAD_WAT`;
* `check_anthro_heat.py` — τ-инвариантность антропогенных потоков;
* `compare_exch_coef.py` (+ `sensitivity_zd.py`) — коэффициенты обмена
  поверхность↔каньон / поверхность↔атмосфера.

Числовые протоколы конкретных прогонов и стендов (морфологии, даты, значения
разностей) приведены в `TEB_Ru_change_history.md`.
