# Диагностическая прокси-модель сада (TEB-Ru)

Документ описывает **реализованную** диагностическую схему сада TEB-Ru:
физическую постановку, математику, структуру кода, параметры, диагностики и
внешние режимы (`EXT` / `EXT_NEU`).

Смежные документы:

* `TEB_Ru_tau_scheme_T_CAN_reformulation.md` — tau-схема дороги и семантика
  температур каньона (`T_CAN0`, `T_CAN1`, `T_CAN`), с которыми связан сад;
* `TEB_Ru_source_defects.md` — дефекты исходного TEB, найденные и исправленные
  в ходе работы;
* `TEB_Ru_change_history.md` — история версий схемы и протоколы измерений.

> Состояние кода: коммит `c37b29c` (2026-09-20), ветка `MV_devs`.

**Аннотация.** Историческая прокси-заглушка сада основана на фиксированном
соотношении Боуэна и не имеет ни ночного длинноволнового охлаждения, ни
конденсации, ни связи с воздухом каньона (`PAC_GARDEN = 0`). Реализованная схема
заменяет её **диагностическим** балансом энергии поверхности с относительной
влажностью поверхности: температура поверхности находится из нелинейного уравнения
`Rn(Ts) = H(Ts) + LE(Ts)` методом Ньютона. Обмен с грунтом не моделируется
(`G = 0`) — сад в TEB не имеет прогностического столба почвы. Схема дополнена
τ-расщеплением связи сада с воздухом каньона и с воздухом уровня форсинга
(аналог τ-схемы дороги).

## 1. Назначение, режимы и место в коде

**Назначение.** Схема даёт согласованный энергобаланс поверхности сада и
участвует в неявной связи температуры и влажности воздуха каньона
(`PAC_GARDEN` / `PAC_AGG_GARDEN` ненулевые), чего историческая заглушка не делала.

**Режимы (`namelist tebparam`, ключ `teb_type_garden`):**

| значение | смысл |
| --- | --- |
| `'PROXY_NEW'` | диагностический баланс энергии (по умолчанию) |
| `'PROXY_OLD'` | исторический прокси Боуэна (`PH = 0.2·Rn`, `LE = 0.8·Rn`, `PAC = 0`) |
| `'EXT'` | внешняя модель сада (модель получает потоки извне); коэффициенты обмена — полный `URBAN_EXCH_COEF` (с устойчивостью и тепловой шероховатостью) |
| `'EXT_NEU'` | внешняя модель сада, но её диагностические коэффициенты обмена считаются по **нейтральной** формулировке внутренней схемы (без `SURFACE_RI` и `z0h`, с тем же минимумом ветра) |

Тип сада хранится в `TOP%CTYPE_GARDEN` (`src/src_struct/modd_teb_optionn.F90`);
недопустимое значение останавливает расчёт (`STOP 1`).

**Параметры поверхности** (ключи намлиста, значения по умолчанию):

| ключ | смысл | по умолчанию |
| --- | --- | --- |
| `urb_z0_gdn` | шероховатость сада, м | `0.1` (`XZ0_GD` из `src/src_proxi_SVAT/modd_proxi_svat_par.F90`) |
| `urb_alb_gdn` | альбедо сада | `0.15` |
| `urb_emis_gdn` | излучательная способность сада | `0.98` |

Все три ключа проверяются в драйвере (шероховатость `<= 0` или `>= XUNDEF`,
альбедо вне `[0, 1)`, излучательная способность вне `(0, 1]` → `STOP 1`), выводятся
в логе модели и передаются всем потребителям: внутреннему прокси
(`PZ0_GD`/`PALB_GD`/`PEMIS_GD` для `GARDEN`, `GARDEN_TAU`), внешним моделям
(семейство `ZZ0_GARDEN_EXT`/`PALB_GD_EXT`/`PEMIS_GD_EXT`) и бюджету радиации
каньона (`URBAN_SOLAR_ABS` с `ZALB_GD`, `URBAN_LW_COEF` с `ZEMIS_GD`). Благодаря
этому TEB и внутренние прокси не могут разойтись в параметрах по построению.

## 2. Физическая постановка

Уравнение баланса энергии на поверхности растительности:

```
Rn(Ts) = H(Ts) + LE(Ts)
```

Поток тепла в подстилающую поверхность не учитывается (`G = 0`): сад в TEB —
диагностическая поверхность без столба почвы и без резервуара тепла.

| член | формула | смысл |
| --- | --- | --- |
| `Rn` | `(1 − alb)·SW + emis·(LW − σ·Ts⁴)` | радиационный баланс (короткая + длинная волна) |
| `H` | `ρ·cp·Ca·(Ts − Ta)` | явный тепловой поток |
| `LE` | `ρ·Lv·Ca·(PHU·qs(Ts) − qa)` | скрытый тепловой поток |
| `G` | `0` | теплообмен с грунтом не моделируется |

Обозначения:

* `alb`, `emis` — альбедо и излучательная способность поверхности (ключи намлиста §1);
* `SW`, `LW` — приходящая коротковолновая и длинноволновая радиация (поглощённые
  садом потоки TEB передаёт внутрь схемы);
* `σ` — постоянная Стефана–Больцмана (`XSTEFAN` из `MODD_CSTS`);
* `Ta`, `qa` — температура и удельная влажность эталонного воздуха (для
  τ-расщепления — смесь, см. §2.3);
* `ρ` — плотность воздуха, `cp` — теплоёмкость влажного воздуха при постоянном
  давлении (`XCPD`), `Lv` — скрытая теплота парообразования (`XLVTT`);
* `Ca` — аэродинамическая проводимость, м/с (§2.1);
* `PHU` — относительная влажность поверхности (`XPHU_GD = 0.8`);
* `qs(Ts)` — удельная влажность насыщения при температуре поверхности
  (`QSAT`/`DQSAT` из `MODE_THERMOS`).

### 2.1 Проводимость и трение

Нейтральный логарифмический профиль с нижним пределом скорости ветра:

```fortran
PCD = (kappa / LOG(PZ/PZ0))**2                         ! 0 при PZ <= PZ0
Ca  = PCD * MAX(PV, XVMIN_GD)                          ! XVMIN_GD = 0.5 м/с
PUW = -Ca * V                                          ! поток импульса
PAC = Ca                                               ! проводимость для TEB
```

где `κ` — постоянная Кармана (`XKARMAN`), `PZ` — опорная высота, `PZ0` —
шероховатость (`urb_z0_gdn`), `PV` — модуль скорости ветра на опорной высоте.

**Зачем нужен минимум ветра.** Без него при штиле `Ca = 0`, поверхность полностью
отвязывается от воздуха, и её температура перестаёт быть привязанной к `Ta`
(в радиационном пределе `Ts → (LW/σ)^(1/4) = T_sky`). Нижний предел скорости
обеспечивает ненулевой теплообмен и делает задачу корректной **без искусственных
ограничений на `Ts`**: при `Vmin = 0.5` м/с получаем `ρ·cp·Ca ≈ 5…9 Вт/м²/К`, что
в ясную ночь при `Rn ≈ −70 Вт/м²` даёт `Ts ≈ Ta − 4…14 K` — в физичном диапазоне.

**Единый источник формулировки.** Нейтральные выражения собраны в
`MODE_GARDEN_BALANCE` (`src/src_proxi_SVAT/garden.F90`) в виде двух
`ELEMENTAL`-функций:

| функция | формула |
| --- | --- |
| `GARDEN_PCD_NEUTRAL(PZ, PZ0)` | `PCD = (κ/ln(PZ/PZ0))²`, `0` при `PZ ≤ PZ0` |
| `GARDEN_CA_NEUTRAL(PZ, PZ0, PV)` | `Ca = PCD·max(PV, XVMIN_GD)` |

Их используют:

* `GARDEN` — коэффициент `PCD` внутреннего сада без τ-расщепления;
* `GARDEN_TAU` — проводимости каньонной и атмосферной ветвей (`Ca_C`, `Ca_A`);
* `URBAN_DRAG` — блок `TOP%CTYPE_GARDEN == 'EXT_NEU'` (каньон: высота `PZ_LOWCAN = H/2`
  и ветер `PU_LOWCAN`; атмосфера: `PUREF` и `PVMOD`);
* эмулятор внешней модели `PCD_GARDEN` в offline-драйвере (§9).

Поэтому минимум ветра нигде не дублируется, а экспортируемые моделью
коэффициенты и внутренняя схема описывают **один и тот же** объект. Для режима
`'EXT_NEU'` это означает `PCDN = PCD = PCH` (одна формула на импульс и тепло), а
`PRI_GARDEN_*` и `ZZ0H_GARDEN_*` не определены и остаются `XUNDEF` (как у
внутреннего сада). У режима `'EXT'` коэффициенты считаются полным
`URBAN_EXCH_COEF` (с устойчивостью и `z0h = z0/4`), поэтому он на 16–35 % ниже
нейтрального — именно этим `'EXT_NEU'` отличается от `'EXT'`.

### 2.2 Решение нелинейного уравнения (метод Ньютона)

Уравнение `F(Ts) = 0` и его производная:

```
F(Ts)  = (1 − alb)·SW + emis·(LW − σ·Ts⁴)
         − ρ·cp·Ca·(Ts − Ta)
         − ρ·Lv·Ca·(PHU·qs(Ts) − qa)

F'(Ts) = −[ 4·emis·σ·Ts³ + ρ·cp·Ca + ρ·Lv·Ca·PHU·dqsat/dT ]
```

Итерация (`ZDEN = −F' > 0`):

```fortran
DO JITER = 1, NITER_GD          ! NITER_GD = 8
   ZQSAT  = QSAT (ZTS_GD, PPS)
   ZDQSAT = DQSAT(ZTS_GD, PPS, ZQSAT)          ! точная dqsat/dT из MODE_THERMOS
   ZNUM   = (1-alb)*SW + emis*(LW - XSTEFAN*ZTS_GD**4)                     &
            - rho*XCPD*Ca*(ZTS_GD - T_REF) - rho*XLVTT*Ca*(XPHU_GD*ZQSAT - Q_REF)
   ZDEN   = 4.*emis*XSTEFAN*ZTS_GD**3 + rho*XCPD*Ca + rho*XLVTT*Ca*XPHU_GD*ZDQSAT
   ZDELTA = ZNUM / ZDEN                        ! = F / (−F'), 0 при ZDEN <= 1e-8
   ZTS_GD = ZTS_GD + MAX(-XDTSTEP_GD, MIN(XDTSTEP_GD, ZDELTA))   ! |dTs| <= 5 K
   ZTS_GD = MAX(XTSMIN_GD, MIN(XTSMAX_GD, ZTS_GD))                ! [230, 350] K
ENDDO
```

Численные особенности:

* начальное приближение — `PTS_GARDEN` (`INOUT`-аргумент): используется значение
  с предыдущего шага, поэтому при повторных вызовах с тем же входом результат
  зависит от начального приближения (в песочнице это учитывается сбросом `Ts`
  перед вызовом, иначе сравнения «бит-в-бит» теряют смысл из-за разного числа
  эффективных шагов Ньютона);
* каждый шаг ограничен `5 K`, абсолютные границы `[230, 350] K` — только
  численная страховка (нужны для корректности `qs(Ts)` и `σ·Ts⁴`); ограничения на
  `|Ts − Ta|` нет: нижний предел скорости ветра делает их избыточными;
* решатель возвращает **неклиппованные** потоки; клиппинги (`XHMAX_GD`, `XLEMAX_GD`,
  `XLEMIN_GD`) применяет вызывающая подпрограмма, поэтому клиппинг может слегка
  нарушить точное равенство `Rn = H + LE` (в штатных условиях он не срабатывает).

### 2.3 Тау-ветви сада (связь с каньоном и с атмосферой)

Сад остаётся **одной поверхностью** с одной температурой `Ts`; τ интерполирует её
связь с двумя воздушными массами — так же, как это сделано для бюджета дороги:

```fortran
Ca_C   = (kappa/LOG(PZ_LOWCAN/PZ0_GD))**2 * MAX(PU_LOWCAN, XVMIN_GD)   ! каньон, уровень H/2
Ca_A   = (kappa/LOG(PUREF/PZ0_GD))**2     * MAX(PVMOD,     XVMIN_GD)   ! атмосфера, уровень PUREF
Ca_eff = PTAU*Ca_C + (1.-PTAU)*Ca_A
T_ref  = (PTAU*Ca_C*PT_LOWCAN + (1.-PTAU)*Ca_A*PTA) / Ca_eff           ! guard Ca_eff > 0
q_ref  = (PTAU*Ca_C*PQ_LOWCAN + (1.-PTAU)*Ca_A*PQA) / Ca_eff
```

Уравнение баланса решается **один раз** с агрегатом `(Ca_eff, T_ref, q_ref)` (одна
поверхность, один радиационный бюджет), после чего фактический поток и ветви
равны

```
H_GARDEN  = ρ·cp·Ca_eff·(Ts − T_ref)        H_GARDEN_CAN = ρ·cp·Ca_C·(Ts − PT_LOWCAN)
                                            H_GARDEN_ATM = ρ·cp·Ca_A·(Ts − PTA)
LE_GARDEN = ρ·Lv·Ca_eff·(PHU·qs(Ts) − q_ref)   LE_GARDEN_CAN/ATM — аналогично
```

поэтому тождества выполняются точно:

```
H_GARDEN  = τ·H_GARDEN_CAN + (1−τ)·H_GARDEN_ATM        (то же для LE)
Rn_GARDEN = H_GARDEN + LE_GARDEN                       (G = 0)
```

**Три случая** (включение: `LTAU_SPLIT = TOP%LTAU_SCHEME .AND. TOP%CTYPE_GARDEN == 'PROXY_NEW'`):

| `teb_type_garden` | ветвь CAN | ветвь ATM | `H_GARDEN` | эффект τ |
| --- | --- | --- | --- | --- |
| `'PROXY_NEW'` | решение с каньонной связью | то же решение со смешанной связью | `τ·H_CAN + (1−τ)·H_ATM` | есть |
| `'PROXY_OLD'` | предписано `0.2·Rn` | **то же значение** | `0.2·Rn` | нет |
| `'EXT'`, `'EXT_NEU'` | поток внешней модели | **то же значение** | поток внешней модели | нет |

Для `'PROXY_OLD'` и внешних режимов, а также при выключенной схеме `Ca_A = 0`,
смешивание не выполняется, и **обе ветви принудительно равны фактическому
потоку**: эти режимы по построению не чувствительны к тому, с каким форсингом
посчитан поток, поэтому равенство ветвей корректно (и тождество
`H = τ·H_CAN + (1−τ)·H_ATM` выполняется тривиально).

**Куда подставляются ветви:**

| приёмник | что входит |
| --- | --- |
| `T_CAN0` (`avg_urban_fluxes.F90`) | `Ts·PAC_GD·ZGD` — каньонная проводимость, без τ (как `T_rd`/`PAC_RD` у дороги) |
| `PQ_CAN0` | `qsat(Ts)·PAC_AGG_GD·PHU·ZGD` |
| `T_CAN1` (приток свободного слоя) | `ZGD·PH_GARDEN_ATM` |
| `PQ_CAN1` | `ZGD·PLE_GARDEN_ATM` |
| городской баланс (`PH_TWN`, `PH_GRND`, `PLE_TWN`, `LE_GRND`, `PEVAP_TWN`) | `PH_GARDEN`/`PLE_GARDEN` — τ-бленд |

Радиационные величины сада (`XABS_SW_GARDEN`, `XABS_LW_GARDEN`, `ZEMIT_LW_GD`) и
влажностный узел `PQ_CAN0` используют единственную `Ts`, поэтому осреднение
радиационных членов не требуется.

**Пределы и свойства:**

* `teb_ltau_scheme = .FALSE.` (и любой тип сада): смешивание выключено, ветви
  равны фактическому потоку — поведение модели до τ-схемы воспроизводится
  бит-в-бит;
* `τ = 1` при включённой схеме: смешивание пропускается, решение совпадает с
  каньонным, `H_GARDEN = H_GARDEN_CAN` **точно**; меняется только диагностика
  свободного слоя (`T_CAN1`, `PHI_CAN1`), в которую теперь входит атмосферная
  ветвь сада;
* `τ → 0`: `H_GARDEN = H_GARDEN_ATM`, `T_CAN = T_CAN1`;
* клиппинги потоков (`XHMAX_GD`, `XLEMAX_GD`, `XLEMIN_GD`) применяются к
  фактическому потоку; тождества §2.3 выполняются точно везде, где клиппинг не
  срабатывает, а при срабатывании остаток имеет порядок клиппинга;
* вырождений нет: `Ca_A = 0` при `z0 ≥ PUREF`, а `Ca_eff > 0` гарантирован
  минимумом ветра каньонной ветви; guard на `Ca_eff > 0` защищает `T_ref`/`q_ref`;
* поток импульса сада (`PUW_GARDEN`) остаётся каньонным, как и у дороги: τ-схема
  импульс не делит;
* **одна температура поверхности** — осознанное решение: две независимые `Ts`
  («затенённая/открытая часть сада») требуют либо разрыва замыкания `Rn = H + LE`,
  либо рассинхронизации узлов `T_CAN0`/`T_CAN1`, а выигрыш по потокам ≤ 1 Вт/м²
  (см. §5.3 в `TEB_Ru_change_history.md`).

## 3. Структура кода

`src/src_proxi_SVAT/garden.F90` содержит модуль `MODE_GARDEN_BALANCE` и **три**
подпрограммы сада.

| подпрограмма | назначение | проводимость | трение / ветви | кто вызывает |
| --- | --- | --- | --- | --- |
| `GARDEN_TAU` | сад TEB **с τ-схемой**: ветви `_CAN`/`_ATM`, одна температура поверхности | считает `Ca_C` и `Ca_A` (высоты `H/2` и `PUREF` — внутри) | сам (`PUW = −Ca_C·max(u_c, Vmin)`, ветви) | модель (`TEB_GARDEN`) — единственный вход из TEB |
| `GARDEN` | сокращённый диагностический сад **без τ** (поведение модели до τ-схемы) | считает `PCD = (κ/ln(z/z0))²` и вызывает `GARDEN_PCD` | **один** набор потоков (ветвей в подписи нет) | только эксперимент |
| `GARDEN_PCD` | тот же баланс при **внешнем** безразмерном `PCD` и внешнем эталонном состоянии (`PT_REF`, `PQ_REF`, ветер `PV_GD`) | **не считает**: `Ca = PCD·max(V, Vmin)` | **один** набор потоков: `PUW` — сам | только эксперимент |

Модуль `MODE_GARDEN_BALANCE` (в том же файле) содержит параметры схемы
(`XPHU_GD`, `XVMIN_GD`, шаг и пределы Ньютона, клиппинги), **единственный** решатель
`GARDEN_BALANCE(PCA, PT_REF, PQ_REF, …)` и две `ELEMENTAL`-функции нейтральной
формулировки (`GARDEN_PCD_NEUTRAL`, `GARDEN_CA_NEUTRAL`, §2.1). Решатель вызывают и
`GARDEN_PCD`, и `GARDEN_TAU` (последний — с τ-смешанной проводимостью, которую
нельзя выразить парой `PCD·max(V, Vmin)`).

Взаимные вызовы разрешены интерфейсами из `MODI_GARDEN` (`USE MODI_GARDEN, ONLY : GARDEN_PCD`
в `GARDEN`, `ONLY : GARDEN` в `GARDEN_TAU`), поэтому промежуточных «core»-рутин нет.

Все три поддерживают и `'PROXY_NEW'`, и `'PROXY_OLD'`/`'EXT'` (исторический
прокси Боуэна: `PAC = 0`, `PCD` используется только потоком трения `PUW = −PCD·V²`).
**Разложение по ветвям** (`PH_GARDEN_CAN/ATM`, `PLE_GARDEN_CAN/ATM`) возвращает
только `GARDEN_TAU`: это единственная рутина, знающая обе проводимости и оба
эталонных воздуха. `GARDEN` и `GARDEN_PCD` возвращают **один** набор потоков;
«плоскую» подстановку (обе ветви = поток, так что бленд
`H = τ·H_CAN + (1−τ)·H_ATM` тривиален) делает вызывающий — сам `GARDEN_TAU` в не-τ
ветви и TEB для внешнего сада.

Аргументные списки компактны: **в аргументах `GARDEN_PCD` нет ни высоты, ни `z0`**
(они уже свёрнуты в переданный `PCD`); неиспользуемые легаси-параметры
(`HIMPLICIT_WIND`, `TPTIME`, `PTSUN`, `PPEW_*`, `PPET/PPEQ_*`, `PTSTEP`, `PEXNS`,
`PCO2`, `PRR`, `PSR`, `PZENITH`) из всех трёх рутин удалены, вызов в
`teb_garden.F90` соответственно сокращён.

Для отладочных прогонов используется внешняя песочница (вне репозитория):
драйвер `test_garden.F90` + `build.ps1`, которые собирают физику **прямо из
репозитория** (`garden.F90`, `modi_garden.F90` и зависимости: `hook`,
`modd_csts`, `modd_reprod_oper`, `modd_surf_par`, `mode_thermos`, `ini_csts`).
Она позволяет сравнивать `GARDEN`/`GARDEN_PCD`/`GARDEN_TAU` бит-в-бит на наборах
условий (летний день и ночь, зима, штиль, сухая жара, вырожденный `z0`).

| --- | --- | --- |

| `XTSMIN_GD` | 230 K | нижняя граница `Ts` (численная страховка) |
| `XTSMAX_GD` | 350 K | верхняя граница `Ts` (численная страховка) |

| `XLEMAX_GD` | 1000 Вт/м² | предел `LE` |
| `XLEMIN_GD` | −200 Вт/м² | предел конденсации (`LE` вниз) |
| порог `ZDEN` | 1e-8 | ниже — шаг Ньютона обнуляется |

Ограничения на разность `|Ts − Ta|` нет: она избыточна, поскольку минимум ветра
(`Vmin`) гарантирует ненулевой теплообмен и удерживает `Ts` вблизи `Ta`.
Абсолютные границы `[230, 350] K` нужны только для корректности `qs(Ts)` и
`σ·Ts⁴`. Клиппинг потоков — страховка: он слегка нарушает точное равенство
`Rn = H + LE`, но при штатных условиях не срабатывает, и замыкание выполняется на
уровне сходимости Ньютона.

## 7. Примечания к физике

* **`PHU` — относительная влажность поверхности, а не насыщение.** При `PHU = 0.8`
  сад отдаёт 80 % потенциального испарения в приземный воздух; `PHU = 1` —
  насыщенная поверхность.
* **`PHU = 0` — артефакт линейной схемы.** Формула даёт
  `LE = ρ·Lv·Ca·(0 − qa) < 0`, т.е. «сухая» поверхность конденсирует атмосферную
  влагу. Практически `PHU` не должен быть равен нулю. Более корректная сухая
  поверхность требует `q_surf = min(PHU·qs(Ts), qa)`, что выходит за рамки
  линейной диагностической схемы.
* **Обмена с грунтом нет (`G = 0`).** Сад — диагностическая поверхность без столба
  почвы и без резервуара тепла (в отличие, например, от прогностической ISBA с
  «памятью» слоя). Энергобаланс замыкается мгновенно: `Rn = H + LE`.
* **Минимум ветра — условие корректности, а не косметика.** Именно он заменяет
  искусственные ограничения на `Ts`: в штилевую ясную ночь он удерживает `Ts`
  вблизи `Ta` (см. §2.1).
* **Ночью** (`SW = 0`) работает длинноволновое охлаждение: схема даёт отрицательные
  `H` (охлаждение) и, возможно, отрицательные `LE` (роса), если `PHU·qs(Ts) < qa`.
  Это главное физическое улучшение по сравнению с заглушкой Боуэна, у которой при
  `SW = 0` потоки обращаются в ноль.
* **Днём при высоком `PHU`** возможен «оазисный» режим: `LE` превышает `Rn`, и
  недостающее тепло поверхность берёт из воздуха (`H < 0`, `Ts < Ta`). Это
  физически корректное поведение сильно увлажнённой поверхности; при `PHU = 0.8`
  оно реализуется в заметной части дневных шагов, поэтому для типичного городского
  газона `PHU` следует брать в диапазоне 0.3–0.5.

## 8. Интеграция в TEB

* **`PAC_GARDEN` / `PAC_AGG_GARDEN` ненулевые** (в исторической заглушке они были
  нулевыми). В `src/src_teb/avg_urban_fluxes.F90` узел температуры каньона получает
  слагаемое `PTSRAD_GD·PAC_GD·ZGD`, а узел влажности —
  `PQSAT_GD·PAC_AGG_GD·PHU_AGG_GD·ZGD`, т.е. сад входит в неявную связь с воздухом
  каньона.
* **`PGFLUX_GARDEN` остаётся нулевым** в обеих схемах (обмена с грунтом нет),
  поэтому `PGFLX_GRND` и `PGFLX_TWN` не меняются.
* **Согласованность диагностики.** `DMT%XABS_SW_GARDEN`, `DMT%XABS_LW_GARDEN` и
  `ZEMIT_LW_GD` пересчитываются в `teb_garden.F90` по той же решённой `ZTSRAD_GD`;
  при тех же `PALB`/`PEMIS` возвращаемый `RN` и пересчитанная диагностика
  совпадают.
* **Садовые диагностики выводятся в `TEB_output.csv`** (на м² сада, §4).
* **τ-ветви** (§2.3) входят в узел `T_CAN0` каньонной ветвью, а в свободный слой
  `T_CAN1` — атмосферной; подробности семантики `T_CAN0`/`T_CAN1`/`T_CAN` —
  в `TEB_Ru_tau_scheme_T_CAN_reformulation.md`.

## 9. Внешний сад и эмулятор в offline-драйвере

**Режимы `'EXT'` и `'EXT_NEU'`.** Сад задаётся извне: TEB получает от внешней
модели через штатный интерфейс `teb_ts_gd`, `teb_qs_gd`, `teb_shfl_gd`,
`teb_lhfl_gd`, `teb_qvfl_gd`, `teb_runoff_gd`. Отличие режимов — в диагностических
коэффициентах обмена, которые считает `URBAN_DRAG`:

| режим | формулировка коэффициентов | кто использует |
| --- | --- | --- |
| `'EXT'` | полный `URBAN_EXCH_COEF` (с устойчивостью `SURFACE_RI` и `z0h = z0/4`) | сопряжение с внешней моделью, коэффициенты на 16–35 % ниже нейтральных |
| `'EXT_NEU'` | нейтральная формулировка внутреннего сада (`GARDEN_PCD_NEUTRAL`/`GARDEN_CA_NEUTRAL`) | рекомендуемый режим сопряжения: экспортируемые коэффициенты совпадают с теми, по которым работает диагностический баланс |

**Эмулятор в offline-драйвере.** Если выбран `teb_type_garden = 'EXT'` (или
`'EXT_NEU'`), offline-драйвер (`src/src_driver/run_teb_offline.F90`) сам играет роль
внешней модели сада (contained-подпрограмма `PCD_GARDEN`). `call_driver`/TEB при
этом не меняются и не знают, эмуляция это или настоящая внешняя модель: они видят
штатный интерфейс `EXT`.

Поток данных на каждом подшаге (сразу после `CALL teb_interface`):

1. строятся оба пути τ-расщепления сада — теми же формулами и с теми же
   высотами/`z0`, что и `GARDEN_TAU`: `PCD_C = (κ/ln((H/2)/z0))²`, `V_C = max(ZU_CANYON, Vmin)`,
   `PCD_A = (κ/ln(hlev_teb/z0))²`, `V_A = max(|V_forc|, Vmin)`, `τ` — та же
   tanh-релаксация H/W;
2. форсинг, который отдаётся «внешней модели»: `V* = τ·V_C + (1−τ)·V_A` (τ-средний
   ветер), `T* = T_CAN`, `q* = Q_CAN`; радиация — `SW`/`LW`, восстановленные из
   поглощённых садом потоков TEB (`XABS_SW = (1−alb)·SW_rec`, `XABS_LW = ε·(LW_rec − σTs⁴)`);
3. **эффективные коэффициенты** (поправка на ковариацию τ-осредования):
   `CH_eff = Ca_eff/max(V*, Vmin)`, так что `CH_eff·max(V*, Vmin) ≡ Ca_eff`
   (ковариационный член `τ(1−τ)(Cd_C−Cd_A)(V_A−V_C)` снят тождественно);
   `CD_eff = Ca_C·max(V_C, Vmin)/max(V*, Vmin)²` — трение, как в модели, остаётся
   на каньонной ветви;
4. вызов `GARDEN_PCD('PROXY_NEW', CH_eff, V*, T*, q*, …)`: тот же диагностический
   баланс и те же параметры, что у внутренней схемы. Полученные `Ts`, `H`, `LE`,
   `EVAP` и `qs = XPHU_GD·QSAT(Ts)` записываются в прогностические переменные
   драйвера — их TEB прочтёт на следующем подшаге.

**Диагностика эмулятора:** строка в логе о режиме и (однократно) контрольное
тождество `CH_eff·max(V*, Vmin) − Ca_eff`; в CSV (только в режимах `EXT`/`EXT_NEU`) —
13 колонок `EMU_*` (§4).

**Отличия эмуляции от внутренней схемы (структурные):**

* в режиме `EXT`/`EXT_NEU` `PAC_GD = 0`: сад **не входит** в неявные узлы
  `T_CAN0`/`Q_CAN0`, тогда как внутренняя схема сама меняет воздух каньона. Это
  главный остаточный источник расхождения, и он растёт с τ;
* разложение на ветви не эмулируется: обе ветви несут один и тот же поток
  (`H_GARDEN_CAN = H_GARDEN_ATM = H_GARDEN`), тогда как внутренняя схема даёт
  реальные ветви;
* связь односторонняя с лагом в один подшаг; первый подшаг — спин-ап связи
  (`Ts = T` воздуха, потоки нулевые), его желательно исключать из статистики.

## 10. Ограничения и открытые вопросы

1. **Проводимость атмосферной ветви `Ca_A` не публикуется отдельной колонкой**
   (она восстанавливается из `H_GARDEN_ATM`, `Ts` и `PTA`): имя `PAC_GARDEN_ATM`
   занято диагностикой `URBAN_DRAG` для режима `EXT`.
2. **Разделение входящей радиации** сада между затенённой и открытой частями (SVF)
   не делается: τ меняет только аэродинамическую связь — как и у дороги.
3. **Скорость ветра каньона в атмосферной ветви** берётся как ветер на уровне
   крыши (`PVMOD`), а не как локальный профиль над садом.
4. **В режиме `EXT`/`EXT_NEU` сад не входит в неявную связь с воздухом каньона**
   (`PAC_GD = 0`, §9): при реальных τ (порядка 0.06 для LCZ9) эффект мал, при
   плотном каньоне он станет основным — тогда потребуется передать внешней модели
   и её проводимость в каньон (новый вход интерфейса `EXT`).
5. **Остаточная ошибка эмулятора структурна** (единая смесь `T* = T_CAN`, отсутствие
   неявной связи, лаг в один подшаг) и не является сдвигом по времени; её величины
   по сайтам и морфологиям — в `TEB_Ru_change_history.md`.
6. **Нет физиологии растительности**: `PHU` фиксирована, нет фотосинтеза (`PSFCO2 = 0`),
   нет зависимости устьичного сопротивления от влаги почвы и CO₂, нет полива, стока
   и дренажа (`PIRRIG = PRUNOFF = PDRAIN = 0`), нет обмена с грунтом (`G = 0`).
7. **`PHU = 0` физически не осмыслен** в линейной схеме (§7).
