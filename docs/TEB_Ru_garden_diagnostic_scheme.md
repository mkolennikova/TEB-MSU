# Диагностическая прокси-модель сада и зелёной крыши (TEB-Ru)

Настоящий документ описывает предлагаемую замену внутренней прокси-заглушки
сада (`GARDEN`) и зелёной крыши (`GREENROOF`), которая сейчас основана на
фиксированном соотношении Боуэна, на диагностическую схему с замкнутым
энергобалансом поверхности и относительной влажностью поверхности
(«подход B»).

> Статус: **предложение**. Здесь зафиксирована физическая постановка,
> структура кода, параметры и ограничения. Сама реализация — в отдельных
> файлах `src/src_proxi_SVAT/`.

---

## 1. Мотивация

Текущая реализация в `src/src_proxi_SVAT/garden.F90` и
`src/src_proxi_SVAT/greenroof.F90` сводится к прокси Боуэна:

```fortran
PRN = (1 - alb) * PSW          ! albedo зашито 0.15
PH  = 0.2 * PRN                ! Bowen ratio = 0.25
PLE = 0.8 * PRN
PGFLUX = 0                     ! поток в подстилающую поверхность пренебрегается
PAC  = 0                       ! аэродинамическая проводимость обнулена
```

Свойства этой заглушки:

- **нет ночного охлаждения**: при `SW = 0` потоки обращаются в ноль, длинноволновое
  радиационное охлаждение (`LW`) не учитывается;
- **нет конденсации/росы**: скрытый поток всегда `>= 0`;
- **нет обратной связи с воздухом каньона**: `PAC_GARDEN = 0` и
  `PAC_AGG_GARDEN = 0`, поэтому в `avg_urban_fluxes.F90` сад не участвует в
  неявной связи температуры и влажности воздуха каньона
  (`PTSRAD_GD * PAC_GD * ZGD` и `PQSAT_GD * PAC_AGG_GD * PHU_AGG_GD * ZGD`
  в нуле).

Предлагаемая схема устраняет эти ограничения, оставаясь **диагностической**
(без прогностических переменных почвы/влаги): температура поверхности находится
из нелинейного уравнения баланса методом Ньютона. Обмен с грунтом при этом
**не вводится** (`G = 0`), как и в исторической схеме: сад в TEB не имеет
прогностического столба почвы.

---

## 2. Физическая постановка

Уравнение баланса энергии на поверхности растительности:

```
Rn(Ts) = H(Ts) + LE(Ts)
```

Поток тепла в подстилающую поверхность не учитывается (`G = 0`): сад в TEB —
диагностическая прокси-поверхность без столба почвы / резервуара тепла, поэтому
обмен с грунтом не моделируется (так же, как в исторической схеме).

Члены:

| Член | Формула | Смысл |
|------|---------|-------|
| `Rn` | `(1 - alb)·SW + emis·(LW - σ·Ts⁴)` | net radiation (короткая + длинная волна) |
| `H`  | `ρ·cp·Ca·(Ts - Ta)` | явный тепловой поток |
| `LE` | `ρ·Lv·Ca·(PHU·qs(Ts) - qa)` | скрытый тепловой поток |
| `G`  | `0` | теплообмен с грунтом не моделируется |

Обозначения:

- `alb`, `emis` — альбедо и излучательная способность поверхности;
- `SW`, `LW` — входящая коротковолновая и длинноволновая радиация;
- `σ` — постоянная Стефана–Больцмана (`XSTEFAN` из `MODD_CSTS`);
- `Ta`, `qa` — температура и удельная влажность воздуха (на высоте опорного уровня);
- `ρ` — плотность воздуха;
- `cp` — теплоёмкость воздуха при постоянном давлении (`XCPD`);
- `Lv` — скрытая теплота парообразования (`XLVTT`);
- `Ca` — аэродинамическая проводимость (м/с), профиль нейтральной стратификации;
- `PHU` — относительная влажность поверхности (0..1);
- `qs(Ts)` — удельная влажность насыщения при температуре поверхности.

### 2.1 Параметризация проводимости и трения

Нейтральный логарифмический профиль с нижним пределом скорости ветра:

```fortran
V   = MAX(V, V_min)               ! V_min = 0.5 м/с
Ca  = (k / ln(zref/z0))² · V      если zref > z0, иначе Ca = 0
PAC = Ca
PUW = -Ca · V
```

где `k` — постоянная Кармана (`XKARMAN`), `z0` — шероховатость поверхности,
`V` — модуль скорости ветра, `zref` — опорная высота (`PZ_LOWCAN` для сада,
высота атмосферного уровня для крыши).

**Зачем нужен `V_min`.** Без него при штиле `Ca = 0`, поверхность полностью
отвязывается от воздуха, и её температура перестаёт быть привязанной к `Ta`
(в радиационном пределе `Ts → (LW/σ)^(1/4) = T_sky`). Нижний предел скорости
обеспечивает ненулевой теплообмен и делает задачу корректной **без каких-либо
искусственных ограничений на `Ts`**. При `V_min = 0.5 м/с` получаем
`ρ·cp·Ca ≈ 5…9 Вт/м²/К`, что в ясную ночь при `Rn ≈ −70 Вт/м²` даёт
`Ts ≈ Ta − 4…14 K` — в физичном диапазоне.

### 2.2 Решение нелинейного уравнения (метод Ньютона)

Уравнение `F(Ts) = 0`:

```
F(Ts) = (1-alb)·SW + emis·(LW - σ·Ts⁴)
        - ρ·cp·Ca·(Ts - Ta)
        - ρ·Lv·Ca·(PHU·qs(Ts) - qa)
```

Аналитическая производная (для шага Ньютона; к формулам приводятся производные
`σ·Ts⁴` и линеаризованного `qs`):

```
F'(Ts) = -[ 4·emis·σ·Ts³ + ρ·cp·Ca + ρ·Lv·Ca·PHU·dqsat/dT ]
```

Итерация (знак согласован: `ZDELTA = F / (-F')`):

```fortran
ZQSAT  = QSAT (Ts, P)
ZDQSAT = DQSAT(Ts, P, ZQSAT)       ! точная dqsat/dT из MODE_THERMOS
ZDELTA = ZNUM / ZDEN                ! ZDEN = -F' > 0
Ts     = Ts + ZDELTA
```

Каждый шаг Ньютона ограничен (`|ΔTs| ≤ 5 K`); абсолютный предел `[230, 350] K`
— только численная страховка. Ограничения на `|Ts - Ta|` нет.

## 3. Структура кода

### 3.1 Расположение

Солвер встроен **непосредственно в `src/src_proxi_SVAT/garden.F90`** (внутри ветки
`TYPE_GARDEN == 'PROXY_NEW'`): отдельного файла-солвера нет, но выбор схемы и
параметры задаются намлистом:

| Ключ намлиста | Смысл |
|---|---|
| `teb_type_garden` | выбор модели: `'PROXY_OLD'` (исторический Bowen-прокси), `'PROXY_NEW'` (по умолчанию), `'EXT'` (внешняя модель) |
| `urb_z0_gdn` | шероховатость сада (м) — **одна для всех версий сада**; по умолчанию `XZ0_GD = 0.10` из модуля `src/src_proxi_SVAT/modd_proxi_svat_par.F90` |
| `urb_alb_gdn` | альбедо сада; по умолчанию `0.15` (раньше — константа `XALB_GD` в `garden.F90` и `TEB_VEG_PROPERTIES`) |
| `urb_emis_gdn` | излучательная способность сада; по умолчанию `0.98` (раньше — константа `XEMIS_GD` и `TEB_VEG_PROPERTIES`) |
| `urb_z0_grf` | шероховатость зелёной кровли (м); по умолчанию `XZ0_GR = 0.01` (раньше — число `0.01` в `greenroof.F90`) |
| `urb_alb_grf` | альбедо зелёной кровли; по умолчанию `0.15` (раньше — число `0.15` в `greenroof.F90`) |
| `urb_emis_grf` | излучательная способность зелёной кровли; по умолчанию `0.98` (раньше — `0.9` в драйвере; входит в `PEMIS_TWN`/`PTS_TWN` и в диагностику поглощённой длинноволновой радиации) |

Шероховатость передаётся солверу аргументом `PZ0_GD`, альбедо и излучательная
способность — аргументами `PALB_GD`/`PEMIS_GD` (интерфейс —
`src/src_proxi_SVAT/modi_garden.F90`, вызов — `src/src_teb/teb_garden.F90`), а во внешнюю
модель — обычным путём `teb_z0_gd/teb_alb_gd/teb_emis_gd → ZZ0_GD_EXT/... →
PZ0_GARDEN_EXT/PALB_GD_EXT/PEMIS_GD_EXT` (у зелёной кровли — семейство `..._GR_EXT`,
в прокси `GREENROOF` — `PALB_GR`/`PEMIS_GR`/`PZ0_GR`). Те же значения уходят в
бюджет радиации каньона: `URBAN_SOLAR_ABS` (`ZALB_GD`, `ZALB_GRF`) и `URBAN_LW_COEF`
(`ZEMIS_GD`, `ZEMIS_GR`), так что TEB и внутренние прокси согласованы по
построению. Недопустимое значение (шероховатость `<= 0` или `>= XUNDEF`, альбедо
вне `[0, 1)`, излучательная способность вне `(0, 1]`) останавливает расчёт
(`STOP 1`); эффективные значения видны в логе модели (`TEB-Ru offline: urb_z0_gdn =
...`, `garden alb/emis = ...`). Модуль `modd_proxi_svat_par.o` добавлен в
`Makefile`; `garden.F90` больше не зависит от него (значения приходят сверху).

Использование физических констант и утилит (соответствует реальным именам в
`TEB-Ru`):

```fortran
USE MODD_CSTS,    ONLY : XCPD, XLVTT, XKARMAN, XSTEFAN
USE MODE_THERMOS   ! QSAT, DQSAT
```

> Внимание: в `MODD_CSTS` **нет** переменной `XCP` — используется `XCPD`
> (сухой воздух). Постоянную Стефана–Больцмана не следует заводить заново —
> берётся `XSTEFAN`.

## 4. Численные предохранители

| Величина | Значение | Назначение |
|----------|----------|------------|
| `XTS_MIN` | 230 K | нижняя граница `Ts` (только численная страховка) |
| `XTS_MAX` | 350 K | верхняя граница `Ts` (только численная страховка) |
| `XDT_STEP` | 5 K | предел шага Ньютона |
| `XH_MAX` | 1000 Вт/м² | предел `|H|` |
| `XLE_MAX` | 1000 Вт/м² | предел `LE` |
| `XLE_MIN` | -200 Вт/м² | предел конденсации (`LE` вниз) |
| `NITER` | 8 | число итераций Ньютона |

Ограничения на разность `|Ts - Ta|` **нет**: она избыточна, поскольку нижний
предел скорости ветра (`Vmin`) гарантирует ненулевой теплообмен и удерживает
`Ts` вблизи `Ta`. Абсолютные границы `[230, 350] K` нужны только для корректности
`qs(Ts)` и `σ·Ts⁴`; в августовском московском форсинге они не достигаются
(проверено на трёх конфигурациях ЛКЗ: 0 срабатываний из 767 шагов).

Клиппинг потоков — страховка: он слегка нарушает точное равенство `Rn = H + LE`.
При штатных условиях он не срабатывает, и замыкание выполняется на уровне
сходимости Ньютона (см. §7).

## 5. Примечания к физике

- **`PHU_AGG` — относительная влажность поверхности, а не насыщение.** При
  `PHU = 0.8` сад отдаёт 80 % потенциального испарения в каньон; при `PHU = 0.3`
  зелёная крыша — существенно меньше; `PHU = 1` — насыщенная поверхность.

- **`PHU = 0` — артефакт.** Формула даёт `LE = ρ·Lv·Ca·(0 - qa) < 0`, т.е.
  «сухая» поверхность конденсирует атмосферную влагу. Практически `PHU` не
  должен быть равен нулю (в этой линейной схеме). Более корректная сухая
  поверхность требует `q_surf = min(PHU·qs(Ts), qa)`, что выходит за рамки
  линейной диагностической схемы.

- **Обмена с грунтом нет (`G = 0`).** Сад — диагностическая прокси-поверхность
  без столба почвы и без резервуара тепла: поток в подстилающую поверхность не
  моделируется (в отличие, например, от прогностической ISBA, где есть
  «память» слоя). Энергобаланс замыкается мгновенно: `Rn = H + LE`.

- **Нижний предел скорости ветра (`Vmin = 0.5 м/с`) — не косметика, а условие
  корректности.** Именно он заменяет собой искусственные ограничения на `Ts`:
  в штилевую ясную ночь он удерживает `Ts` вблизи `Ta` (см. §2.1).

- **Ночью** (`SW = 0`) работает длинноволновое охлаждение: схема даёт
  отрицательные `H` (охлаждение) и, возможно, отрицательные `LE` (роса), если
  `PHU·qs(Ts) < qa`. Это главное физическое улучшение по сравнению с заглушкой
  Боуэна.

- **Днём при высоком `PHU`** возможен «оазисный» режим: `LE` превышает `Rn`, и
  недостающее тепло поверхность берёт из воздуха (`H < 0`, `Ts < Ta`). Это
  физически корректное поведение сильно увлажнённой поверхности; при `PHU = 0.8`
  оно реализуется в заметной части дневных шагов, поэтому для типичного
  городского газона `PHU` следует брать в диапазоне 0.3–0.5.

## 6. Влияние на интеграцию в TEB

- **`PAC_GARDEN` / `PAC_AGG_GARDEN` становятся ненулевыми.** В
  `avg_urban_fluxes.F90` узел температуры каньона получает слагаемое
  `PTSRAD_GD · PAC_GD · ZGD`, а узел влажности — `PQSAT_GD · PAC_AGG_GD · PHU_AGG_GD · ZGD`,
  т.е. сад входит в неявную связь с воздухом каньона (в исторической схеме эти
  коэффициенты нулевые).

- **`PGFLUX_GARDEN` остаётся нулевым** в обеих схемах (обмена с грунтом нет),
  поэтому `PGFLX_GRND` и `PGFLX_TWN` не меняются.

- **Согласованность диагностики.** `DMT%XABS_SW_GARDEN`,
  `DMT%XABS_LW_GARDEN`, `ZEMIT_LW_GD` пересчитываются в `teb_garden.F90` по
  той же решённой `ZTSRAD_GD`; при тех же `PALB`/`PEMIS` возвращаемый `RN` и
  пересчитанная диагностика совпадают.

- **Садовые диагностики выводятся в `TEB_output.csv`** (по м² сада):
  `TS_GARDEN`, `RN_GARDEN`, `H_GARDEN`, `LE_GARDEN`, `EVAP_GARDEN`,
  `QSAT_GARDEN`, `PHU_GARDEN`, `PAC_AGG_GARDEN`, `PAC_GARDEN`.

- **Тау-схема дороги распространяется на сад.** При `teb_ltau_scheme = .TRUE.` и
  `teb_type_garden = 'PROXY_NEW'` схема сада решает свой баланс с **τ-смешанной**
  связью: `Ca_eff = τ·Ca_canyon + (1−τ)·Ca_atmosphere` (каньонная ветвь — воздух
  `PT_LOWCAN`/`PQ_LOWCAN` на высоте `H/2`, атмосферная — `PTA`/`PQA` с ветром `PVMOD`
  на высоте `PUREF`), а её фактический поток равен `τ·H_GARDEN_CAN + (1−τ)·H_GARDEN_ATM`
  (то же для `LE`). Каньонная ветвь входит в узел `T_CAN0`, атмосферная — в свободный
  слой `T_CAN1`; обе считаются от **одной** температуры поверхности (как `T_rd` у
  дороги). Для `'PROXY_OLD'` (поток не зависит от форсинга) и `'EXT'` (один комплект
  потоков, уже посчитанный для осреднённого форсинга) ветви принудительно равны
  фактическому потоку, т.е. τ-схема их не меняет. Дополнительные столбцы:
  `H_GARDEN_CAN/ATM`, `LE_GARDEN_CAN/ATM`. Подробности — часть IV документа
  `TEB_Ru_tau_scheme_T_CAN_reformulation.md` (§26).

### 7.2 Чувствительность к `urb_z0_gdn` (`python_tests/garden_z0_sensitivity.py`)

### 7.7 Три подпрограммы сада и песочница (структура кода)

`src/src_proxi_SVAT/garden.F90` содержит **три подпрограммы** и модуль с параметрами
схемы и единственным решателем:

| подпрограмма | назначение | проводимость | трение/ветви | кто вызывает |
|---|---|---|---|---|
| `GARDEN_TAU` | сад TEB **с τ-схемой**: ветви `_CAN`/`_ATM`, одна температура поверхности | считает `Ca_C` и `Ca_A` (высоты `H/2` и `PUREF` внутри) | сам (`PUW=−Ca_C·max(u_c,Vmin)`, ветви) | модель (`TEB_GARDEN`) — единственный вход из TEB |
| `GARDEN` | сокращённый диагностический сад **без τ** (поведение модели до τ-схемы) | считает `PCD = (κ/ln(z/z0))²` и вызывает `GARDEN_PCD` | **один** набор потоков (ветвей в подписи нет) | только эксперимент |
| `GARDEN_PCD` | тот же баланс при **внешнем** безразмерном `PCD` и внешнем эталонном состоянии (`PT_REF`,`PQ_REF`, ветер `PV_GD`) | **не считает**: `Ca = PCD·max(V,Vmin)` | **один** набор потоков: `PUW` — сам, ветвей нет | только эксперимент |

`MODULE MODE_GARDEN_BALANCE` (в том же файле) содержит параметры схемы
(`XPHU_GD`, `XVMIN_GD`, шаг/пределы Ньютона, клиппинги) и **единственный**
решатель `GARDEN_BALANCE(PCA, PT_REF, PQ_REF, …)`; его вызывают и `GARDEN_PCD`,
и `GARDEN_TAU` (последний — с τ-смешанной проводимостью, которую нельзя выразить
парой `PCD·max(V,Vmin)`). Там же лежат две `ELEMENTAL`-функции нейтральной
формулировки — `GARDEN_PCD_NEUTRAL` и `GARDEN_CA_NEUTRAL` (см. §7.10): их общий
минимум ветра `XVMIN_GD` и использует и внутренний сад (`GARDEN`, `GARDEN_TAU`),
и внешний сад `'EXT_NEU'` (`URBAN_DRAG`). Взаимные вызовы разрешены интерфейсами из
`MODI_GARDEN` (`USE MODI_GARDEN, ONLY : GARDEN_PCD` в `GARDEN`, `ONLY : GARDEN` в
`GARDEN_TAU`), поэтому промежуточных «core»-рутин нет.

Все три поддерживают и `'PROXY_NEW'`, и `'PROXY_OLD'`/`'EXT'` (исторический
Bowen-прокси: `PAC = 0`, `PCD` используется только потоком трения `PUW = −PCD·V²`).
**Разложение по ветвям (`PH_GARDEN_CAN/ATM`, `PLE_GARDEN_CAN/ATM`) возвращает только
`GARDEN_TAU`** — это единственная рутина, которая знает обе проводимости и оба
эталонных воздуха. `GARDEN` и `GARDEN_PCD` возвращают **один** набор потоков:
«плоскую» подстановку (обе ветви = поток, так что блендинг
`H = τ·H_CAN+(1−τ)·H_ATM` тривиален) делает вызывающий — сам `GARDEN_TAU` в не-τ
ветви и, для внешнего сада, TEB; в эксперименте S-1 — драйвер, а настоящее
разложение эмулируемого сада восстанавливает `BRANCH_EMU`.
**В аргументах `GARDEN_PCD` нет ни высоты, ни `z0`**: они уже свёрнуты в
переданный `PCD`. Аргументные списки компактны — неиспользуемые легаси-параметры
(`HIMPLICIT_WIND`, `TPTIME`, `PTSUN`, `PPEW_*`, `PPET/PPEQ_*`, `PTSTEP`, `PEXNS`,
`PCO2`, `PRR`, `PSR`, `PZENITH`) из всех трёх рутин удалены; вызов в
`teb_garden.F90` соответственно сокращён.

по всем 96 столбцам CSV, плюс полный стенд `compare_garden_scheme.py`

### 7.8 Эмулятор внешней модели сада в offline-драйвере (`run_teb_offline.F90`)

Реализовано (без новых модулей и без новых ключей намелиста): если выбран
`teb_type_garden = 'EXT'`, то драйвер сам играет роль внешней модели сада.
`call_driver`/TEB при этом **не меняются и не знают**, эмуляция это или настоящая
внешняя модель: они видят только штатный интерфейс `EXT` (им на вход идут
`teb_ts_gd`, `teb_qs_gd`, `teb_shfl_gd`, `teb_lhfl_gd`, `teb_qvfl_gd`,
`teb_runoff_gd`).

**Поток данных (на каждом подшаге, сразу после `CALL teb_interface`):**

1. contained-подпрограмма `PCD_GARDEN` строит два пути τ-расщепления сада — теми же
   формулами и с теми же высотами/`z0`, что и `GARDEN_TAU`:
   `PCD_C = (κ/ln((H/2)/z0))²`, `V_C = max(ZU_CANYON, Vmin)`;
   `PCD_A = (κ/ln(hlev_teb/z0))²`, `V_A = max(|V_forc|, Vmin)`;
   `Ca_eff = τ·Ca_C + (1−τ)·Ca_A`, `τ` — та же tanh-релаксация H/W.
2. Форсинг, который отдаётся «внешней модели»: `V* = τ·V_C+(1−τ)·V_A` (τ-средний
   ветер), `T* = T_CAN`, `q* = Q_CAN` (первое приближение; τ-средний воздух —
   следующий шаг), радиация — `SW/LW`, восстановленные из поглощённых садом
   потоков TEB (`XABS_SW = (1−alb)·SW_rec`, `XABS_LW = ε·(LW_rec − σTs⁴)`).
3. **Эффективные коэффициенты** (поправка на ковариацию τ-осреднения):
   `CH_eff = Ca_eff/max(V*,Vmin)` — так что `CH_eff·max(V*,Vmin) ≡ Ca_eff`
   (ковариационный член `τ(1−τ)(Cd_C−Cd_A)(V_A−V_C)` снят тождественно);
   `CD_eff = Ca_C·max(V_C,Vmin)/max(V*,Vmin)²` — трение, как в модели, остаётся на
   канальной ветви.
4. Вызов `GARDEN_PCD('PROXY_NEW', CH_eff, V*, T*, q*, …)`: тот же диагностический
   баланс, что у внутренней схемы (те же `XPHU_GD=0.8`, `XVMIN_GD=0.5`, тот же
   Ньютон). Полученные `Ts, H, LE, EVAP` и `qs = XPHU_GD·QSAT(Ts)` записываются в
   прогностические переменные драйвера — их TEB прочтёт на следующем подшаге.

**Диагностика:** в лог — строка о режиме и (один раз) контрольное тождество
`CH_eff·max(V*,Vmin)−Ca_eff`; в CSV (только в режиме `EXT`) — 13 новых столбцов
`EMU_TAU, EMU_CD_EFF, EMU_CH_EFF, EMU_CH_NAIVE, EMU_V, EMU_T, EMU_Q, EMU_CA_CAN,
EMU_CA_EFF, EMU_TS, EMU_H, EMU_LE, EMU_EVAP` (описание — в

### 7.10 Внешний сад с нейтральными коэффициентами обмена (`teb_type_garden = 'EXT_NEU'`)

Новое **значение** существующего ключа (`CTYPE_GARDEN` длиной 9 символов, новых
ключей нет): сад по-прежнему задаётся извне, но диагностические коэффициенты
обмена сада считаются **по нейтральной формулировке внутренней схемы** — без
устойчивости (`SURFACE_RI`) и без тепловой шероховатости (`z0h`), с тем же

`PCDN = PCD = PCH` (одна формула на импульс и тепло), `PAC` — из

определены и остаются `XUNDEF` (как и у внутреннего сада). Колонки CSV те же, что

(бит-в-бит) и совпадение τ=1 таблицы `check_physics.py` с архивом.

### 7.11 τ = 0.5: графики «честный внутренний сад против эмулятора внешней модели»

Худший случай τ-осреднения — τ ≈ 0.5 (ковариационный член
`τ(1−τ)(Cd_C−Cd_A)(V_A−V_C)` максимален). Чтобы получить его при **любой**
морфологии, порог tanh-релаксации в намелисте берётся равным H/W сайта
(`teb_tau_hw_thresh = urb_h2w`, метка `'HW'` в `mk_nml.py`): тогда `tanh(0) = 0` и
τ = 0.5 **точно**. Набор стенда (`tau_garden_check`): для LCZ2 (H/W = 1.5),
LCZ6 (0.5), LCZ9 (0.15), SPARSE (0.0086) — по три прогона
`<site>_gNEW_tau05` (честная внутренняя схема — эталон), `<site>_gEXT_tau05`
(эмулятор `EXT`) и `<site>_gEXTNEU_tau05` (эмулятор с нейтральным экспортом
`EXT_NEU`), плюс база `<site>_gNEW_tau0` (τ-схема выключена, τ = 1) как масштаб
самого эффекта τ-схемы.

**Проверки постановки** (все — `plot_tau05.py`): τ, восстановленное из потоков
ветвей честного прогона, `= 0.500000` на всех четырёх сайтах; тождество
`H = τH_CAN+(1−τ)H_ATM` — `max|d| = 2–4·10⁻¹²` Вт/м²; `EMU_TAU = 0.5`;
`max|Ca(честный) − Ca(EXT_NEU)| = 0` (бит-в-бит, 767 шагов × 4 сайта); τ-агрегат
`EMU_CA_EFF` нейтрального экспорта равен агрегату честной схемы
`τ·Ca_C+(1−τ)·Ca_A` с точностью `1·10⁻¹⁷` м/с; три новых кейса LCZ6 совпадают с
ранее посчитанными `LCZ6_*_tau1` (тот же τ = 0.5) **бит-в-бит** — 0 отличающихся
столбцов (`cmp_runs.py`).

**Ошибки эмулятора против честной схемы** (среднее/rmse за месяц, Вт/м²; для `Ts`
— K) и эффект самой τ-схемы (τ = 0.5 против τ = 1):

| сайт | `Ts` (`EXT` / `EXT_NEU`) | `H_GARDEN` (`EXT` / `EXT_NEU`) | `LE_GARDEN` (`EXT` / `EXT_NEU`) | эффект τ-схемы (`H` / `LE` / `Ts`) |
|---|---|---|---|---|
| LCZ2 | +0.176 / +0.158 | −3.98 (rmse 5.13) / −3.46 (4.80) | +2.77 (4.78) / +2.21 (4.50) | +27.0 / −31.2 / +1.00 |
| LCZ6 | +0.041 / +0.004 | −4.59 (5.41) / −3.00 (4.20) | +4.21 (6.38) / +2.66 (5.05) | +10.7 / −13.0 / +0.49 |
| LCZ9 | +0.018 / −0.019 | −6.09 (7.55) / −4.09 (5.81) | +5.86 (8.69) / +4.01 (6.76) | +1.9 / −3.9 / +0.37 |
| SPARSE | +0.019 / −0.013 | −5.97 (7.79) / −4.12 (6.15) | +5.84 (9.00) / +4.17 (7.19) | −0.6 / −1.1 / +0.31 |

1. **Нейтральный экспорт ближе к честной схеме**: \|bias\| по `H_GARDEN` падает на
   13–33 % (LCZ6: 4.59 → 3.00 Вт/м²), rmse — на 6–23 %, по `Ts` — с 0.041 до 0.004 K.
   Это прямое следствие того, что эмулятор сам решает баланс по нейтральным
   коэффициентам: `EXT_NEU` отдаёт ему ровно их, `EXT` — коэффициент с Ri и z0h,
   которого эмулятор не воспроизводит (стратифицированный экспорт даёт проводимость
   каньона 0.38–0.46 от честной, т.е. в 2.2–2.6 раза меньше).
2. Остаточная ошибка **структурная**, а не от τ-осредования (ковариационный член
   снят тождественно, см. проверки): единая смесь `T* = T_CAN`, отсутствие неявной
   связи сад↔каньон в режиме `EXT` (`PAC_GD = 0`) и лаг в один подшаг. При τ = 0.5
   на LCZ6 эмулятор забирает ≈ половину эффекта τ-схемы (rmse 5.4 против 10.7 Вт/м²);
   на разреженных LCZ9/SPARSE сам эффект τ мал (1–2 Вт/м²), и остаточные ≈6 Вт/м²
   его превышают.
3. Ошибка не является сдвигом по времени: корреляция `H_GARDEN` максимальна при
   нулевом лаге (≈1.000), распределение ошибки сосредоточено в дневные часы.
4. В режиме `EXT` разложение на ветви **не эмулируется** — обе ветви несут один и тот
   же поток (`H_GARDEN_CAN = H_GARDEN_ATM = H_GARDEN`), тогда как честная схема даёт
   реальные ветви, различающиеся на LCZ6 при τ = 0.5 на 40–60 Вт/м².
